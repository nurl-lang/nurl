# Tokeniser-aware token efficiency

> Generated by `bench/token_efficiency.py`. Lower is better.

Encoders used:

* **`cl100k`** — `cl100k_base`. The tokeniser GPT-3.5 / GPT-4 / Claude legacy use.
* **`o200k`** — `o200k_base`. GPT-4o and the o-series.
* **`gpt2`** — the smaller BPE that LLaMA derivatives share their byte-pair shape with at this granularity. Llama 3's own tokeniser is HF-gated; gpt2 is used as a proxy.

All counts use `encode_ordinary` — special-token sequences inside string literals stay literal data.

## Notes on interpretation

These tokenisers were trained on Python / Rust / JS corpora. Their BPE merges common multi-character sequences in those languages into single tokens (`def `, `function `, `for i in range`, `let mut`, `=>`). NURL source is not in any of these corpora, so NURL keyword-shaped tokens decompose to individual character pairs.

The Rust column for `json_parse` (1140–2065 tokens) reflects Serde derive macros and explicit type signatures that other languages do not require for the same task.
