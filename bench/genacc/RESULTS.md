# NURL generation accuracy & token report

Generated by `bench/genacc/score.py`. Every figure is **first-pass**: the model's first and only attempt, with no human edits and no self-repair. *compile* = built with zero changes; *correct* = printed the exact expected bytes (a program that compiles but prints the wrong answer is a miss); *tokens* = the BPE token cost of the program the model emitted.

> Reproducible with any model — see `bench/genacc/README.md`. The conditions below are whichever solution directories were passed in; a name containing `noprimer` is the no-reference condition.

**Read every NURL number in this light:** public LLMs contain **zero lines of NURL** in their training data — against (order-of-magnitude) **tens of millions** of lines of Python and **millions** of lines of Rust. The NURL rows are a language the model has never seen once, working only from the in-context reference.

## Headline — a 10× bigger primer (full grammar) did not help

This run swaps the focused **v2 reference (≈1,330 tokens)** for a **14,098-token** reference (the entire `grammar.ebnf` plus a large worked example). Same 4 held-out string tasks, same 3 models, 5 samples each. The previous (v2) numbers are preserved in [`RESULTS_old.md`](RESULTS_old.md); the previous primer in [`primers/nurl_old.md`](primers/nurl_old.md).

| model | held-out compile / correct — **v2 (1,330 tok)** | held-out compile / correct — **grammar (14,098 tok)** |
|---|---:|---:|
| `claude-opus-4-8` | 85% / 75% | 75% / 75% |
| `claude-sonnet-4-6` | 60% / 60% | **0% / 0%** |
| `claude-haiku-4-5` | 50% / 50% | 60% / 60% |
| Python / Rust (either primer) | 100% / 100% | 100% / 100% |

**The 10× larger reference did not improve held-out accuracy.** haiku ticks up (50→60%), opus dips on compile (85→75%, correct flat at 75%), and sonnet **collapses to 0%**. Meanwhile the per-request prompt overhead rose from 1,330 to **14,098 tokens** (Python and Rust still pay zero). On both axes that matter — accuracy *and* tokens — the big primer is worse for two of the three models.

**Why: the same single failure, untouched (or worsened).** The dominant error is still the forgotten `$` import for stdlib string functions — **20 of 20** sonnet failures and **6 of 8** haiku failures are exactly `unknown function 'nurl_str_len'`. The models write otherwise-clean, idiomatic NURL and drop one boilerplate import line; burying that line inside a 14k-token grammar dump made sonnet drop it *every single time*. (opus's failures were instead 4 syntax slips — "cannot be a call target".) Import discipline is a specific, prominent-cue problem; more volume does not solve it and can dilute it. **The focused 1,330-token v2 primer was the better artifact.**

**Context for the gap.** With tens of millions of Python lines and millions of Rust lines in training versus **zero** for NURL, even handing the model the complete grammar in-context does not buy the parity in-distribution languages get for free. The honest reading is unchanged and now better supported: a regular grammar is learnable from a **focused** page, but NURL is **not** at Python/Rust parity, and the binding constraint is **stdlib-import discipline, not grammar size**.

## How to read this (interpretation)

- **First-pass, strictest setting.** No retries, no human edits, no compiler-feedback repair loop. A real agent with NURL's diagnostic-first compiler would do better than these numbers, not worse.
- **The primer is not free.** A NURL request pays ~1.1k extra prompt tokens for the reference, and (see the token columns) NURL programs tend to emit *more* tokens than Python for the same task — consistent with `bench/TOKEN_EFFICIENCY.md`. NURL's case is correctness and learnability, **not** token thrift; we are not hiding that it costs more tokens.
- **Zero NURL in the training data is the headline context.** With the primer withheld, a model cannot write NURL at all — it emits another language verbatim — so that condition scores ~0%. Given only one page of rules it reaches the same ballpark as Python and Rust, languages it has seen millions of lines of. For a language the model has *never seen a line of*, landing near in-distribution languages from a single page is a reasonable-to-strong outcome, and is the affirmative LLM-native signal the token study could not give.
- **No language dominates per task; treat small gaps as noise.** Correct-output differences inside a single-digit percentage on N≈35 are within sampling noise, and the misses are task-specific (e.g. a model may flub one task's spec in *every* language). Compare the *pattern* — primed vs withheld — not a one-task lead.
- **Scope.** A small set of arithmetic/systems micro-tasks, scored on whatever model(s) you generated with. It is a starter signal, not a publication; extend `tasks.json` (verify each new expected output with `bench/verify.sh` first) and add models to firm it up.
