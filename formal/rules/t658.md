| `btree_remove` drops the stored key of the entry it removes last. `__bt_remove_rec` moves the key up into `btree_remove`'s frame (through `kout`; a key whose drop runs no code of the program's own is dropped where it is found, as before), and it is dropped once the leaf, every ancestor's size, the tree's count and the root are final and while the value handed back is still a binding. A key's destructor that panics there leaves a tree without the entry, which goes on being used or is dropped by the unwind, each remaining entry once. Before, the key was dropped inside the recursion with its node still counting the slot (`mem_take` had emptied it), and the tree's own drop ran the destructor again on the empty slot.
