| A value that views a field of its own storage (`vsv_`: `= . o v ( slice_from_vec . o buf )`) takes those views with it when it is stored. Into a struct field whose path is known (`@ P { o 0 }`), the owner it went to depends on the same fields at their new place (`p` on `p.s.buf`, `__bck_sv_carry`). Into a container's element, the container notes which fields of its elements the elements view (`svr_`), and a value of a type with those fields taken back out of it (popped, matched, bound) depends on its own (`__bck_sv_inherit`). Into a container its caller holds (a parameter the function does not own), the store is refused: the caller is told nothing of what the elements view. A literal written as an argument that takes an owner beside a view of it (`( use @ S { sv b } )`), or takes a value that views its own fields, is refused where the callee's final summaries say it may drop, replace or move a buffer of it (`pendslit`, `__bck_slit_check`). A field path an owner was stored into is that owner's storage, not what the value holding it borrows (`sfo_`, `bck_sx_name`), so a view of it is a self-view.
