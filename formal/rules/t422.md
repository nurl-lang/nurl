| What a function makes of its parameters' views reaches its callers. (1) A view parameter (an `s` the caller still owns, a Slice, a struct of views; not `inout`, not `sink`) stands for itself as a source in the function's walk (`pv_`, `bck_sx_name`): it has no borrow sources there, the caller's, so a holder or a result given it, or a local copy of it, used to depend on nothing (agora #341, #346, #370, #380, #454: a store through a loop element, a join or an element binding of the function's own parameter lands in that parameter, `hr_`, as a pair of its answer). (2) The value a function hands back is checked where it returns (`bck_ret_view_check`, now also for a join, a value block or a field read written there, and for a view or a struct of views as well as an owner of them), and the parameters among what it views are the function's answer, `g_fn_rviews`: `k` a parameter's own storage, `^k` only its elements'; a value whose sources are not known views any parameter, as `retclo` answers. A caller's result depends on the arguments at those indices (`bck_sx_ev`, beside `retptr`), through elements when `^k`; a callee whose walk is parked (or not compiled yet) parks its caller behind it (`rvcallees` → `__bck_walk_deferred`), and functions whose walks ask each other's answers — the function calling itself, a cycle — settle them together as their least fixed point: each is walked quietly from "nothing" with its fellows' latest answers until none grows, then once more for its diagnostics (`__bck_walk_scc`, a strongly connected component of the parked walks; agora #422, #404, #442, #341). A part of an argument that owns its storage and holds no view (`vec_at`'s String), read inline as the argument of a call that lends it, is reached through the argument's element, as a binding of it is (`^k`). (3) A view argument consults the callee's `g_fn_vkeeps` pairs as an owner argument does (`bK` rows), so it is tied to the holder the callee stores it in, not to the first argument (agora #370, #346).
