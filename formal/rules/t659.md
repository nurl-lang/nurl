| A `HashMap`, a `Set`, a `Deque` and a `BTree` whose entries may run code of the program's own when dropped (`( mem_drop_runs_code [T] )`, a constant: nurlc's `__drop_runs_code`) release them restartably. An entry leaves the container before its destructor runs — a map's or a set's slot becomes a tombstone and the count goes down, a deque's run leaves its count, a tree's kid is unlinked and its node's key count goes down past the entry — so the container holds exactly the entries still to go whenever a destructor runs; and while the release runs, a record of the releasing frame (`MapRelease`, `SetRelease`, `DqRelease`, `BtRelease`: a library handle over the same control block, forgotten when the release returns) is in the journal. A panic's drain drops the record, whose drop runs the same release again until it returns, catching a later destructor's panic on its own frame (`mem_release_rest`, stdlib/core/mem.nu): every entry after the panicking one is dropped, once, then the buffers, and only then does the panic go on. `map_remove`, and `map_set` / `btree_set` over an existing entry, drop the key that goes after the container is final and before the value they hand back leaves its binding. A container of anything else runs the loop it always did. No checker rule changes: what is accepted and refused is the same (agora #659).
