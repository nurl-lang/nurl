| A call that may panic (`unw` row) is a way out of the function for its `inout` parameters. One with a field a `sink` took and not yet given a value again goes back to a `recover`ing caller with that field empty, so the inout exit check runs there too (__bck_inout_exit_check at kc 45). `unw` rows are now emitted in a function with an `inout` parameter that owns memory, not only one that can hold views. The refill's own call is not counted: `= . h buf ( vec_new [u] )`, the `fieldset` rows right after the `unw` row. ncore: unwind_check refuses an inout parameter with a gone field path, except the place a call's temporary refills (`temp_refill`). A closure's own `inout` parameter goes back to its caller at each exit too: the closure walk's own parameters are its `inout` ones (`&name`, `__clo_inout_amp__`), not the enclosing function's list it read before; ncore: params_hold_locals refuses an inout parameter going back with a gone field. A `?` join's arm that is a binding whole, `^ ? c h h2`, hands that binding on: the conditional records a `pendwhole` row at the arm (kind 48), asked by the partly-moved check; an arm that reads a field of it is untouched. A field a `sink` takes out of a struct whose `% Drop` reads it is refused: the destructor runs at the struct's end and reads the emptied field. Its read set is the receiver fields the impl reads (`dropreads##T`, recorded while it compiles), asked when the module is done (resolve_drop_field_takes); a field it never reads stays accepted. ncore: drop_reads over `drop__T`.
