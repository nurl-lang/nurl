| A declared type's or trait's name holds no `__` past its leading underscores and does not end in `_`, and an import's alias holds no `__`, does not end in `_` and is not the name of a type or trait the program declares (nor may a type declared later take an alias's name). `__` is the compiler's own separator: `( Arc Bag )` is spelled `Arc__Bag`, `( Vec i )` `Vec__i64`, and a module's `Point` imported as `geo` is `geo__Point`. Every rule that asks what a type is (which library handle, which generic, whose instance, what its fields are) reads the name's base, and the base is the declared name whole: its leading underscores, and an import alias with the `__` after it, up to the separator where the type arguments start (`__lty_base_end`, the one reader behind `__lty_base_name`, `__lty_base_is` and `__name_is_inst`). The readers used to cut at the first `__`: a struct named `__Holder`, and a module's `Holder` behind an alias (`hm__Holder`), were asked about under a name no struct has, so the thread rules found no fields and one holding an `Rc` crossed to a thread (a use-after-free). What makes the reading unambiguous is held at the declarations: a struct, enum or trait whose name holds the separator, or ends in `_` (`( Holder_ i )` is `Holder___i64`, a `Holder` of `_i64`), is refused where it stands (`__type_name_guard`; a module's declarations behind an alias are judged by the part after the alias), and the alias where it is written (`__import_alias_check`). `_private`, `__internal`, `my_geo` and `Arc_Bag` are names of a program's own.
