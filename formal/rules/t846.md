| A value block's bindings are the enclosing scope's to the walk, as they are to codegen (MEMORY.md §1, "Where values are dropped"): its `block` row is `vblock`, whose `endblock` ends their *names* (bck_xl_close) and not their lives; `__bck_scope_lets`, `bck_scope_restore` and the in-scope scanners read through it, so they end where the enclosing scope does, and a way out of the block ends them once, with that scope's. A `:` of a value block whose tail is a closure binding of the block is `: g f` to the walk: a borrow of what f borrows (`\|f`). Before, the walk set them uninitialised at the `}`: a view or closure of one handed on later — `^ d` of `: s d { : String t … ( string_data t ) }`, `= b ( id { : String t … t } )` in a loop, `= keep f` inside the block, a `;` defer calling a block-assigned closure — or a view chained through a second binding of the block (`: s e { : s t … : s w t  w }  ^ e`, a slice, an element) — was tied to nothing and read freed memory, while the unblocked spellings were refused (agora #846, #839, #847, #638's rest). Where codegen copies a value block's tail-call lend of the block's own binding into the target (`mem_blk_tail_copy_slot`, agora #190 / #193), the walk is told the target owns that copy (`__bck_unalias_copied`): it is no alias of the binding | §1, §2.3, §5.3 | none: A2 has no value blocks — a block is read in ANF as its statements followed by the binding of its tail, in the enclosing scope (the reading of agora #823's rows), so its binders scope over the rest of that scope, as `StmtT`'s `scope` / `letd` binders do; nurlc's walk now reads it the same way (claude-formal) | an extension: it refuses programs that read freed memory; a view of a block's binding read in the same scope, which codegen keeps alive, and a block's tail-call lend that codegen copies stay accepted (tree sweep: no other verdict changes) |
