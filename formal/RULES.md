# Rules → formal rules

Every ownership rule of [`docs/MEMORY.md`](../docs/MEMORY.md) and the
phase that formalizes it. A rule is **done** when its typing rule is
stated, used in the soundness proof, and every hole probe it is meant to
reject is mapped to it by its `// map:` line (the table `corpus/map.tsv`,
written from those lines by [`tools/fuzz/holes/map.sh`](../tools/fuzz/holes/map.sh)).

Formal rules are Lean names in [`A1/`](A1/) and [`A2/`](A2/) (the same
names, extended): typing rules are constructors of `StmtT`, `RhsT`,
`PushArg` and the call check `CallT`; `kill`, `exitScope` and `derive`
are the context operations they use. A1's calculus has owned `Vec` trees
(a `String` is a `Vec` of bytes); A2 adds structs, enums, closures and
trait objects, panics and the drop journal; threads are A3.

## nurlc forms the calculus reads as forms it has (phase C)

Phase C proves that every program nurlc accepts is well-typed in the
formal rules. For a few of nurlc's forms that proof goes through a
reading of the form as one the calculus already has, not through a rule
of its own. These are the readings for a change to a Vec's or a String's
elements made through something other than its owner (Agora #295, step
0):

| nurlc form | Read as | Formal rule |
|---|---|---|
| A function that changes the elements of a Vec or String it takes as a plain parameter, as the standard library's mutators (`vec_push`, `vec_set`, `vec_clear`, `string_push_*`) take theirs | an `inout b` parameter, `b` the most it does: `realloc` if it only grows it, `drop` if it may drop elements, never `replace` (a plain parameter is not rebound) | `CallT`, `paramOK_inout`, `callPostAux` (the kill by the bound) |
| A change through a copy of one owner's whole handle (`: x ( id vs )`, `: ~ c vs`, a cursor), to its elements only | the same change made on that owner | `StmtT.push`, `RhsT.pop` |
| A change through a field path of an owner (`( vec_push [u] . o kids x )`) | the struct taken apart, its field changed, the struct put back (§2.12) | `StmtT.unpair`, `StmtT.push`, `StmtT.assign` |
| `vec_clear`, `vec_truncate`, `vec_insert`, `vec_remove` | loops of pops and pushes | `RhsT.pop`, `StmtT.push` |

A reading holds only where nurlc's summary of the callee is at least what
the callee does: Agora #315 was a hole in that summary. A replacing
callee (`inout replace`) given a copy is no reading: the replacement
lands in the copy's own slot, so nurlc refuses it (h295, h367–h370). A
change through any other borrow (an element of a Vec of Vecs, a field
viewer, a join of borrows, a call's lent result) needs no reading:
`StmtT.editB` types it (Agora #295, step 5). What stays outside is in
`CLAIM.md`.

## Changes to MEMORY.md and what they do to the proof

Every change to the rules of `docs/MEMORY.md` is recorded here with its
effect on the formal rules: whether it touches a rule that is proven
(**done** above), and whether it **extends** the calculus (a new rule, or
a rule made to reject more: every existing proof still holds) or
**breaks** a proof (a rule made to accept more, which reopens its lemmas).

Each row lives in a file of its own, `formal/rules/t<N>.md` after its
change's Agora task (`t0.md`: the changes that had none), and the table
is written from those files in task order by `tools/formal_rules.py`
(Agora #299). A change adds or edits its own file and never the table,
so two changes never edit the same lines. The release regenerates the
table: until then, a change made since the last release is in its file
only.

### Audit of h426–h974 (agora #104, 2026-10-30)

The rows from agora #165 to #214 and #205 were written in one pass,
against main `20b200d` and `10b54e3`. In every one of these changes the diff to `docs/MEMORY.md`
only moved the probe ranges. No rule text changed: each change brought
nurlc into line with a rule that already held, or fixed the lowering.
Three findings matter to the proof:

- **No change made a rule accept more than A1 / A2 do.** Only two changes
  accept more: the address-free `??` payload (#206) and the field-name
  capture (#214). Each accepts exactly what the calculus already types
  (`projE … .int = intE`; `CapsOK`).
- **Copies are calls.** "Copied where it lent" (#178–#200, #202) is a call
  of the value's clone, which A2 types as a call with an owned result. A
  clone of a `Vec` of integers can even be written in the calculus
  (`RhsT.at`, `StmtT.push`). The clones' bodies are part of the standard
  library's base (B). A value with no clone is refused, as A2 refuses
  returning or storing the lend.
- **Per-call ownership is inside the calculus, through an encoding.**
  #184, #185, #186, #203, #205 and #206 answer at run time whether a
  result is owned. A2 types none of them directly: a binding is owned or
  borrowed for every run. But such a value is, in the calculus, an owner
  cell plus a borrow. The cell is an `inout` option the caller provides
  and the callee fills when the value is fresh. The borrow reaches the
  cell's payload or the argument, and `lends` names both.
  `A2/DynCell.lean` types this encoding with A2's rules and applies
  `memory_safe` and `no_leak_end` to it, on the standard axioms
  (`pick_ok`, `main_safe`, `main_no_leak`). So these shapes rest on the
  proof for the rules. That nurlc's bit behaves as the cell does (the bit
  set exactly when the cell would be `some`, the drop and the move under
  it) is phase C / D, and until then the probes check it.
  `A2/DYN_DESIGN.md` gives the correspondence. It also says why a direct
  mode `.dyn` would reopen the invariant's root lemmas, which the
  encoding avoids.

Most of the holes in this range were in surface forms the calculus has
only as statements: `?` / `??` joins as values, value blocks and their
tails, `\` tries, `;` defers and fall-off values. Each probe family was
the same shape in another one of these forms.
