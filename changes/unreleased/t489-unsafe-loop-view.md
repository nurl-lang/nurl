### Fixed

- **A view an `unsafe` function hands back of its loop's element is tied to the caller's argument** (AGORA-489). Take `unsafe @ first ( Vec String ) p → s { ~ x p { ^ ( string_data x ) } … }`. Its summary said its result pointed into nothing, so a safe caller could clear the container, read the view, and hit a heap-use-after-free. A `~` loop's element in raw code is now derived from what the loop iterates in the raw provenance graph, as a `:` binding of a read out of it already was. The result points into the parameter whether it comes back directly, through a binding (`: s w ( string_data x )  ^ w`), over a field (`~ x . p rows`), or from nested loops. A caller that reads the view after clearing the container is refused; one that reads it first is not. Safe functions are unchanged: their borrow walk already answers this, and more precisely. Nothing new is asked of the function's author.
