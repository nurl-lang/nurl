### Added

- **The kernel builds the certificate's term for programs with closures too** (AGORA-1029 step 6). `C.Elab.elabIR` (`formal/C/Elab.lean`) now also covers closures over numbers and buffers of numbers: a closure's code, its literals, and calls through a closure value.
  - A closure is A2's `.fn [σ] .any`, of one interface per closure type after the program's own functions. A literal packs the code with its captures by value (`.pack`, pairs for more than one); a buffer the closure does not own is captured by name, unless every literal moves it into the environment. A call through a closure is `.callc` of its type's interface. `nurl_println_int` is lowered too.
  - All 13 closure programs of the 62 certify programs are now in the subset (45 in all, 32 before). The 8 the checker accepts get `Elab.lean` and `Cert.elab` (26 bundles, 18 before), so their bundles no longer trust the translator `packages/nurl-cert/src/tolean.nu`.
  - `elabIR` stays stricter than the translator, never laxer. It makes the translator's checks on closures over the whole body and program (a capture's type and mode, a closure copied from another binding or handed to a `sink` parameter, which captures every literal moves in). It also refuses what the translator takes but nurlc does not print: a literal of a function not named as a closure's code, variables out of id order, a closure's code naming a variable it does not declare. Each check has a kernel witness for its refusal and for its well-formed neighbour.
  - `tools/ncore/elab_parity.sh` finds 0 differences and 0 programs `elabIR` takes but the translator refuses, over 166 programs in the subset (101 before). 12 new fixtures in `tools/ncore/elab/` cover the new rules.
  - `nurl-cert` 0.3.1: the skip before Lean (`ELAB_CTORS`) takes the new constructors (`.callc .pack .pair .fst .snd .prod .fn`). It also skips a term that holds one of the closure constructors but no `.fn`, which `elabIR` never builds, so struct programs still skip Lean.
- **Cost:** certify takes 77.1 s over the 62 certify programs against 77.8 s before (−0.9 %; −4.6 % in an earlier run). The 13 closure programs new to the subset take +0.19 to +0.63 s each for their Elab.lean part (5 of them the checker refuses, and spend it too); the other 49 are 5.6 s faster in all, the 18 with Elab.lean among them 3.3 s, since the words are numbers now. The largest peak memory is about the same (2586 MiB against 2581 MiB); a new program's peak is +15 to +71 MiB, and the sum of the peaks is −1.1 %.

### Changed

- **`nurl-cert words` (0.3.1) prints each word as a number**, not a string literal: `nat_lit 0x1`, then the word's bytes from the last to the first, two hex digits each. `C.Elab.wordOf` reads it back into the bytes (`wordOf_encB` proves it inverts the encoding), and `elabIR` compares the words with its keywords as numbers. In Lean 4.35 the kernel builds a string literal's bytes one `push` at a time, which is quadratic in the word's length: the file paths of the `fn` lines cost ≈ 130 ms each. The file is ASCII and needs no escaping, so a core IR that is not well-formed UTF-8 now has words too; one with a NUL byte still has none.
- **`nurl-cert words` leaves out a `sum` line whose name no other word holds.** `elabIR` looks a summary up only by a function's name, a callee's name, or the function a `let … call f` calls. `tools/ncore/elab_parity.sh` checks that `elabIR` answers the same on the full words, and translate_test 1c checks the rule against a Python reading of it.
- **Breaking:** Elab.lean's words are another text, so a 0.3.0 bundle with `Elab.lean` does not verify with 0.3.1 (`verify` makes Elab.lean again from `Program.core` and compares it byte for byte). Migration: certify the program again. A bundle without `Elab.lean` verifies as before.
