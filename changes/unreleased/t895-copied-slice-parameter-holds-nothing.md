### Fixed

- **A slice parameter copied into a struct, option or enum no longer keeps its argument's temporary alive** (AGORA-895). With `@ wrapb [i t → Bag { ^ @ Bag { t 3 } }`, the literal copies `t` into the `Bag` it owns, but the compiler still treated the result as a view of the argument. So `( wrapb ( mk ) )`, the option form `@ ?[i { T a }` and a join `( wrapb ? c ( mk ) a )` leaked the temporary from `( mk )`. The copy is now known to hold nothing of its argument, and the temporary is released at the end of the statement. No source change is needed. A slice whose elements hold views (`[s`) still views what those elements view.
- **A struct temporary read for one field is released, and a slice field leaves it safely** (AGORA-895). These used to leak the struct literal: `( string_len . @ SB { ( string_from `ab` ) 3 } s )`, and the same with a `Vec` or slice field. Reading an owned slice field out of a struct a call returned (`( ln . ( mkb ) s )`, `: [i x . ( mkb ) s`) released the struct under the slice and then read freed memory. The slice now leaves with the read and belongs to the argument or binding that takes it. If the struct has a `% Drop`, the release now runs that drop for the borrow checker as well. So reading a field of an `H` whose drop clears a payload shared through an `Rc` is refused while a view of that payload is still used, where before it read freed memory. Storing such a slice straight into another literal's field (`@ Bag { . ( mkb ) s 4 }`) gives it to that literal, with no extra copy (AGORA-936). Returning it straight from a function still leaks (AGORA-936): bind it first and return the binding.
