### Changed

- **A value holding a trait object is judged by the types that implement the trait, not as a closure nobody can follow** (AGORA-248, docs/MEMORY.md §7.7). Once every impl of the program is registered, the compiler's thread-shared walk reads a `% Trait` object as the union of what its impl types can hold, as it reads an enum by its variants. A value holding one that comes out of a `Vec` element, a join or a call can now be stored into a thread-shared handle (a channel, an `HttpServer`'s drain table), or captured by a closure that crosses to another thread, when no impl can hold a closure or a handle leading back. A trait no type implements has no object and holds nothing. Before, every such store was refused ("what the closure captures cannot be followed"), so `std/net` kept its transport as a raw owner word. A cycle through an impl's handle is still refused, as through a struct's field. New tests `ts_dyn_store_ok`, `ts_dyn_store_no_impl`, `diag_ts_dyn_store_impl_reaches_handle`. Compile time: neutral (self-compile instructions −0.0001 %, peak RSS the same).
