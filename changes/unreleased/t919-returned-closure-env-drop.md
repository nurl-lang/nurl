### Fixed

- **Releasing a closure runs the destructors of what it took over, and the check sees it** (AGORA-919). Take a closure that a call hands back, built over a `sink` argument with a `% Drop` that clears or grows a shared `Rc` payload (`@ mkf sink H h → ( @ i ) { ^ \ → i { … h … } }`). Releasing it ran that destructor. A view taken through another handle on the same `Rc` stayed live, and reading it read freed memory. Such a read is now refused where it happens. This covers a closure bound by `:` or given by `=`, and one made through a forwarder. A closure whose maker does not take the value over, and a destructor that only reads, are not affected.
