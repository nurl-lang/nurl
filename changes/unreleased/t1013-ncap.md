### Added

- **What a certified program can do outside its memory: `N.cap`** (AGORA-1013, certify S3; `formal/A2/Reach.lean`, `formal/A3/Reach.lean`, `formal/C/Caps.lean`, `formal/C/Caps3.lean`, phase C16). A certificate now states which of the program's functions a run can enter, and proves it. The kernel checks that the list is closed under the program's names (a call's callee, a `recover`'s, a destructor's, a call's result frame, a closure literal's code: `C.capsOKB`), and `Cert.n_cap` gives that any program with the same functions at those indices, whatever it has elsewhere, has exactly the same runs, and for a threaded program the same interleavings. A function outside the list never runs. The proof is a new invariant over A2 and A3: every step keeps a configuration naming only such a list, in what is left to run and in what memory holds, and reads the program only at a name it holds (`A2.fns_step`, `A2.steps_agree_iff`, `A3.reach_agree_iff`). No rule or theorem changed; standard axioms only.
- What those functions do outside the program's memory is read off their calls in the core IR, through the library's bodies, down to the runtime's functions, each classed by the new capability table `stdlib/caps.tsv` (one row for each of the standard library's 451 foreign declarations, and prefix rows for the compiler's own built-ins). The bundle copies it as `caps.tsv`. The manifest's `capabilities` lists the functions, their classes and one chain of calls per class. N.cap's sentence says what the program can do and what it never does, for example "Outside its own memory it can only: write to standard output. It never: … read files; … open network connections; …". A program that reaches a runtime function the table does not class (`ffi.unknown`) gets no "never": its sentence ends "Its effects outside its own memory are not bounded." The table, that reading of the core IR, and the binary doing what its model does are the claim's new trust rows (`caps-table`, `caps-attribution`, `caps-binary`). `nurl-cert verify` makes all of it again from the bundle and has Lean prove `Cert.n_cap` again. A conditional certificate (AGORA-1033) gets N.cap too, `assumed` on its assumed functions' rows when its check succeeds (as for any bundle, N.cap is `open` when the table is missing or Lean does not prove the list), and an assumed function's classes come from its real calls, so a call the translation does not cover still shows.
- `tools/check_caps_table.sh`, run by CI: a foreign (`&`) declaration in `stdlib/` with no row in `stdlib/caps.tsv` fails the build. A new declaration adds its row in the same change.

### Changed

- **Certificate bundles (nurl-cert 0.4.0): the claims end with `N.cap`.** The manifest gains the optional `capabilities`, `hashes.caps_lean` and `hashes.caps_tsv` (`docs/dev/certificate.schema.json`). A bundle certified before does not verify with this `nurl-cert verify`: certify it again. Certify is no slower and uses no more memory: 64.56 s against 65.10 s over the certify corpus (−0.8 %), the sum of the peak RSS −0.04 %. The check of the list (about 20 ms a program) and the 5 MB its proof loads are paid back by nurlc's second compile running on a thread beside Lean (`ELAN_TOOLCHAIN` names formal/'s toolchain, so Lean no longer runs inside formal/), by Lean running on two worker threads (`--threads=2`) and by certificates' imports carrying no witness programs. Without `--certify` nothing changes: nurlc and the runtime are untouched.
- **A certificate loads no witness program.** The witnesses that a certificate's imports carried are apart from what the claims use, names unchanged: `A3/ClaimWitness.lean` (`A3.arcDtor_claim` and its kin) and `A3/ReapWitness.lean` (`A3.arcDtor_reaps` and its kin) from `A3/Claim.lean` and `A3/Reap.lean`; `A3/LockGive.lean` (the give-back lemmas A3's claim uses, still `A3.LockDtorWitness.*`); `A2/Dtor.lean` (`A2.Dtor.*`, the destructor guarantee) and `A2/NoRootb.lean` (`A2.DynCell.NoRootb`) from their witness programs; `C/ElabWitness.lean` (`C.Elab.elab_while` and the other elaboration witnesses) and `C/CapsWitness.lean` (`C.reachB`, `C.caps_witness_*`). No theorem changed; `formal/check.sh` prints the same axioms. An accepted program's Lean check loads 1.7 MB less of `C.Elab`, a threaded program's 17 MB less in all (`A2.DtorWitness`, `A2.ArcDtorWitness`, `A2.ArcPanicWitness`, `A3.LockDtorWitness`, `A2.DynCell`'s program).
