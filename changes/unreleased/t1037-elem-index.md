### Changed

- **Growing one element lent by a call keeps a view of another element named by a number literal** (AGORA-1037, docs/MEMORY.md §2.10). `: s d1 ( string_data ( vec_at vs 1 ) )` stays valid past `( string_push_str ( vec_at vs 0 ) … )` when `vs` is a `Vec` of Strings or `Vec`s that a local binding of the function owns. Before, the view was refused ("a value lent from it was passed to 'string_push_str', which may move or free its buffer"). It ends as before when the index is not a literal, when two different literals name elements of `vs` on one line, after anything that may reorder `vs` (a `vec_swap`, a closure that runs, a call that may change it, on any path of a join or in an earlier round of a loop), when `vs` is a parameter, when its elements are structs, and when a function of the program stands between: the view taken through one, the element grown by one, or another binding in the view's expression (CodeRabbit on github#2370 found the last one: `( string_data ( sel ( vec_at vs 0 ) a1 ) )`, `a1` element 1, kept past element 1's growth, read freed memory). This is the shape the formal rules now type: A2 lends an element of an owned `Vec` at its index (`RhsT.atIdx`, `Kind.innerAt`), and a change inside one element keeps what lies inside another (`Eff.dropInAt`, formal/A2/ElemIdxWitness.lean). New tests `diag_borrow_elem_lend_grow_of_a_parameter`, `diag_borrow_elem_lend_grow_of_struct_elements`, `diag_borrow_elem_lend_grow_outside_a2`; the swap and index tests of #2350 come back.
