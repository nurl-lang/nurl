### Changed

- **formal/ is built as Lean modules, and a certificate's Lean check loads only their public part** (AGORA-1043). Every file of `formal/` starts `module`, imports with `public import`, and puts its declarations in an `@[expose] public section`, so definitions keep their bodies and nothing is hidden. No statement, definition or proof script changed. `formal/check.sh` prints the same axioms for all 889 theorems it lists, except ten witness lemmas (`A3.Step.stay`, `A2.subDc_hits_exact`, …) whose proofs, elaborated as modules, no longer use `Classical.choice`; none gained an axiom. The combined file `nurl-cert` checks a bundle with (and the refute run's) is a module too, so Lean loads formal/'s definitions and theorem statements but not their proofs, nor Lean's own private parts. Across the 62 certify programs this cuts a Lean check's peak memory by about 40 % and its time by about 8 % (`docs/dev/CERTIFICATE.md`). certify writes the same Program.lean, Claims.lean, Elab.lean and Caps.lean as before; the manifest pins the new `formal/` tree (`versions.formal_tree`), as after any change to `formal/`. In the combined file the claims are private declarations, so `#print axioms` names them `_private.All.0.Cert.…`, and nurl-cert reads that name as well as `Cert.…`. A file outside `formal/` that imports it is unaffected: a file that is not a module still loads everything. A new file in `formal/` must start the same way (`module`, `public import …`, `@[expose] public section`), because a module can only import modules. `webdocs/scripts/gen-formal-data.mjs` reads `public import` lines.
