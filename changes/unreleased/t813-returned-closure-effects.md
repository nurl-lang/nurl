### Fixed

- **A returned closure's effects are no longer lost when its builder is declared below its caller or is generic, or when it comes back through a function that returns its argument** (AGORA-813). Take `: ( @ v ) c ( mk xs )` with `mk` declared after `main`, or generic (`mk [T]`), whose closure grows `xs`. Running `c` while a view of `xs` lived was accepted, and the view then read a freed buffer. The same happened when the closure was handed back through `@ pick ( @ v ) f → ( @ v ) { ^ f }` or a generic identity `( idg [( @ v )] ( mk xs ) )`. The call's result now carries the builder's effects, resolved once the module has compiled, so these programs are refused as they are when the builder is declared above its caller. A closure that only reads what it captured stays accepted, so iterator-adapter style builders are unaffected. Nothing new is asked of the author.
