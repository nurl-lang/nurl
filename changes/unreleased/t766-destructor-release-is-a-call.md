### Fixed

- **Releasing a value runs its destructor as a call, wherever the release is** (AGORA-766). Take a value whose type has a `% Drop` of the program's own that clears or grows the payload of an `Rc` it holds a share of. When that value was released with no call written there, a view taken through another handle on the same `Rc` stayed live, and reading it afterwards read freed memory. The releases that did this were the end of the value's block or of a loop's round, a `break`, the old value of `=` or of a field, a statement's discarded result, a temporary lent to a call, a `sink` parameter its callee lets go, and a value held in a struct field, an option, an enum payload, a `Vec`, a `Box` or the last share of an `Rc`. Such a read is now refused where it happens, with a message that names the release ("was released at the end of its block, which runs its type's 'drop', which may drop or replace what it holds"). A destructor that only reads the payload ends nothing, and neither does a `sink` helper that keeps the value. Read the view before the release, or take it again after.
