### Fixed

- **A generic struct is Send and Sync by the fields its instance has** (Agora #675). `: Wrap [T] { ( Rc T ) held }` — a `( Wrap i )` was captured by a thread's closure, sent on a `Channel`, kept in a `Locked` or shared in an `Arc` while another share of the same `Rc` stayed behind, and two threads counted one unsynchronised reference count (a double free, a use after free): the Send/Sync derivation looked an instance's fields up under the generic's bare name, where an instance registers them under its own (`Wrap__i64`), and found a struct with no fields. The same struct written without a type parameter was always refused. An instance's fields and enum payloads are read as the instance has them now, in the crossing checks, the frozen-payload rule and the rule that tells an `Arc`-backed handle from an `Rc`-backed one. A generic struct of Send parts (`( Vec T )`, `( Arc T )`, `?T`) crosses as before.
- **Every type argument of a generic is asked whether it is Send and Sync, as the type it is** (Agora #683). `( Vec ?( Rc i ) )` captured by a thread, or an `( Arc ?( Rc i ) )` handed to one, was accepted where `( Vec ( Rc i ) )` and a bare `?( Rc i )` were refused: the derivation read a generic's arguments off the instance's mangled name, where an option is a slug it could not take apart, and skipped it. Each argument is read as the type that was written now, an option no less than a named type, wherever the generic sits (`( Arc ( Vec ?( Rc i ) ) )`, `( Channel ?( Rc i ) )`, a field `?( Rc T )` of a generic struct). `( Vec ?i )`, `( Vec ?String )` and `( Arc ?String )` cross as before.
- **An `ArcWeak` crosses a thread only where the `Arc` it upgrades to may** (Agora #690). `( ArcWeak T )` captured by a `thread_spawn` closure was accepted when `T` is Send but not Sync (a `PNCounter`, a struct holding a `Cell`), where `( Arc T )` is refused; `arc_weak_upgrade` on the other thread then gave it an `Arc` on the same payload, and two threads changed one unsynchronised state. An `ArcWeak`'s payload must be Sync as well as Send, as an `Arc`'s must, and the message names the `ArcWeak` among the ways two threads reach one value. `( ArcWeak ( Locked ( Vec i ) ) )` and `( ArcWeak i )` cross as before.
- **An `Rc`'s `Weak` is no more Send than the `Rc`**. A `( Weak T )` captured by a thread's closure — bare, as a struct field, as a `Vec` element — was accepted; `weak_upgrade` there is a clone of the `Rc` on the same count, which is not atomic (a use after free). It is refused where an `Rc` is, with a message of its own: keep the value in an `Arc` and hand the thread an `ArcWeak`.
- **`% NotSync` on one instance of a generic outranks the generic's `unsafe % Sync` in every rule** (Agora #693). With `unsafe % Sync W { }` and `% NotSync ( W i ) { }`, the crossing checks honoured the opt-out, but the rules that excuse a change made through "a handle that synchronises itself" asked the positive marker alone, and it is found by the generic's name: a function handed a `( W i )` out of an `Arc`'s payload could grow its plain `Vec` on eight threads at once (a double free), directly or any number of generic functions deep. Each of those rules — the frozen payload of an `Arc`, a change through a parameter borrowed by value, the frozen walk of what a read guard lends, the `Arc`-backed and `Rc`-backed handle tests — asks the negative marker first now. The instance the negative marker does not name (`( W b )`) keeps the promise.
