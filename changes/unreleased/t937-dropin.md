### Changed

- **The formal proof keeps a view of a `Vec`'s buffer across a change inside one of its elements** (AGORA-937). An example: `vv` is a `Vec ( Vec i )`, `sw` is a slice of `vv`'s own buffer, and `( vec_set ( vec_at vv 0 ) 0 f )` changes the inside of `vv[0]`. That change moves no element of `vv`, so `sw` stays valid. MEMORY.md §2.10 already says so ("its handles of the elements stay"), and nurlc accepts it. A2 used to end `sw` there, because it gave every change through an element the effect `.drop` on `vv`. It now has an effect for a change strictly inside the elements, `.dropIn`, which keeps the root's views. Its soundness is proved (`MInv.edit_dropE`, `vkeep_view_below`), and the order on effects is now inclusion of what they end. A root that is not a `Vec` keeps `.drop`, since a struct's field lies at the struct's top. This is the first step of typing a call that changes memory its argument's views reach (`formal/A2/THRU_STAGE3_DESIGN.md`). Nothing changes in nurlc.
