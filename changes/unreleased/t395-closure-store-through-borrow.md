### Fixed

- **Inside a closure, a view stored through a borrow of a capture is refused** (AGORA-395). Take a closure that captures `vs : ( Vec s )` and runs `: ( Vec s ) w ( id vs )  ( vec_push [s] w ( string_data loc ) )` with a local `loc`. It stored a view of `loc` into the caller's `vs`, and the caller read freed memory once the closure returned. The same happened with an element borrow (`( vec_at vv 0 )`), with an unbound call as the container (`( vec_push [s] ( id vs ) … )`, `( box_get bx )`), and through an option payload cursor (`?? ov { T w → … }`). The capture rule that refuses `( vec_push [s] vs ( string_data loc ) )` by name now applies to every owner a store through a borrow lands in, so all six are refused with the same diagnostic. A store through a borrow of the closure's own local, or of a value that owns its data, is unchanged. Nothing new is asked of the closure's author.
