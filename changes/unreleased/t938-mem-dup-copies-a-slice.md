### Fixed

- **`mem_dup` of an owned slice makes a copy** (AGORA-938). `( mem_dup t )` of a `[i`, `[s` or other owned slice used to hand back the slice itself, not a copy. A function like `@ dupi [i t → [i { ^ ( mem_dup t ) }` then gave its caller the argument's own buffer, and `( ln ( dupi ( mk ) ) )` freed it twice. `mem_dup` of a slice now copies its buffer, as the diagnostics that suggest "a copy that owns its data (mem_dup, …)" already promised, and the copy belongs to whoever takes it. When the operand is a slice a call or join just made, it is taken instead of copied, so no extra allocation is made. A copy of a slice of views still depends on what the views point into. No source change is needed. Code that relied on `mem_dup` of a slice returning the same buffer now gets an independent copy.
