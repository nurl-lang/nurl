### Fixed

- **A value's views of its own fields go with it when it moves** (AGORA-563). Take a struct whose field views another of its fields, such as `= . o v ( slice_from_vec . o buf )`. It could be moved into a struct literal (`@ P { o 0 }`), or handed inside a literal to a `sink` parameter, and then grown there. A literal written as an argument that holds an owner and a view of it (`( use @ S { sv b } )`) could be grown inside the callee. Either way the view read freed memory afterwards. Now the struct a value moves into is tied to the field at its new place, so growing it ends the view, as it does for the value itself. Such a literal argument is refused where the callee may grow, clear or replace what the view points into. A value pushed into a container and taken back out is not followed yet (AGORA-563 stays open for it). Reading the view, or handing it to a callee that only reads, is not affected.
