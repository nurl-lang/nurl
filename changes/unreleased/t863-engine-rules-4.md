### Fixed

- Compiling a program whose struct nests by value many types of many fields (eight fields eight deep: `compiler/tests/drop_analysis_wide_deep_generic.nu`) no longer walks every path through them to ask whether a zeroed value would run a `% Drop` of the program's: the answer is kept per type (`__zero_drops_user`, from AGORA-865). `nurlc --emit-core` and `--engine` on that test: 39 s → 0.07 s. The ownership engine's type questions (`et_scalar`, `et_owning`, `et_owns_handle`, `et_view_capable`, what a type reaches of the shared handles) walk each named type once per question as well, and so does the reference checker (150 s → 0.2 s); every answer is the one asked before (AGORA-863).
- `nurlc --engine` (the ownership engine, in shadow), and the reference checker with it, now refuse what nurlc refuses in these shapes: a field of a `~` loop's element handed to a `sink` in a `;` block armed in the loop (it runs outside every round); a field of a closure's by-value capture handed to a `sink`; a value that owns memory stored into a field of a by-value parameter, a loop's element, or a closure's by-value capture or parameter (the store is lost and nothing releases it); a fresh raw string stored into a field; a function that keeps, in what its caller holds, a view of a `sink` raw-string parameter it releases; a closure whose body changes, through one capture, what another of its captures views; a view a closure call hands back outliving what it views; a closure over a stack binding handed to `signal_install`. Earlier rules of the batch: a change inside a view field lands where the view points; a closure call's arguments are frozen against what its body does to its captures; a closure stored into a thread-shared handle detaches as one a thread runs; a closure parameter handed on to a closure that runs it is run by the function; a changed argument's exclusivity covers what it is a cursor of. Probes the engine accepts that nurlc refuses: 99 → 72 (AGORA-863).
