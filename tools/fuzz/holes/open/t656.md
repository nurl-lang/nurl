**agora #656: a closure that changes a by-value parameter it captured.** `@ w ( Vec u ) x → v { : ( @ v ) c \ → v { ( vec_reserve [u] x 4096 ) } ( c ) }` — or the literal run by a helper, calling a function that grows `x`, or growing a field of a struct parameter — tells its caller nothing: a `Slice` (or any view) the caller took of the argument before `( w xs )` reads the moved buffer afterwards (heap-use-after-free). A closure handed BACK does the same when the caller runs it: `@ mk ( Vec String ) x → ( @ v ) { ^ \ → v { ( vec_clear [String] x ) } }`, then `: ( @ v ) c ( mk xs )`, a view of `xs`, `( c )`. And where several threads reach the value — the callee of a closure they share, or of an Arc's reader — such an inner closure changes it with no lock, unseen by the thread rules. The same change written in the function's own body is refused at the call. Until the fix ships, change a parameter in the function's body rather than in a closure over it, and take views of an argument after the calls (and after running a closure made from it).
