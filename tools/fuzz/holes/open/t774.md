**agora #774: a `~` loop over an Rc payload of numbers, reset through another handle inside it; a payload view written into an `inout` parameter.** With `r2` a clone of `r` and `pl` its payload, `~ x pl { ( wipe r ) … }` reads freed memory on the next round when the elements are numbers (heap-use-after-free): the loop's cursor over `pl` outlives `pl`'s end. And a callee that writes a view of `( rc_get ( vec_at hs 0 ) )` into an `inout` parameter leaves the caller's view unmarked. Until the fix ships, do not change an Rc's payload through another handle while a loop walks it, and take a view of a payload after the call that changes it.
