**agora #933: a callee that changes a `Vec` it reaches through a slice its `sink` parameter holds, called with another argument that views the same `Vec`.** `@ f sink ( Vec ( Slice ( Vec i ) ) ) vv ( Slice i ) s2` grows `( slice_at ( vec_at vv 0 ) 0 )` (`vec_reserve`, `vec_push`) and then reads `s2`, a view of that same element: the element's buffer moved, and `s2` reads freed memory (valgrind: an invalid read inside a freed block). The callee does not know what its parameters view, and the caller passes `s2` beside a value whose views reach the same `Vec`. With `vv` taken `inout` nurlc refuses it. Until the fix ships, do not pass a view of a `Vec` beside an owner of a slice over that `Vec`'s container to a function that changes elements through it; pass a copy (`slice_to_vec`) of one of them.
