**agora #490: a `~` loop's element moved out — handed to a sink, `string_free`, `vec_free`.** Codegen moves the element out of the container, but the walk ends no view of that element taken before the loop (`: s v ( string_data ( vec_at [String] t 0 ) )  ~ x t { ( string_free x ) }`), which then reads freed memory; the same move through a `vec_at` binding is refused. Until the fix ships, do not move a loop's element out while a view into the container's elements is live; take the elements out with `vec_pop` / `vec_remove` instead.
