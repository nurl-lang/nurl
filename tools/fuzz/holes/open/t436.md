**agora #436: a `~` loop over a Vec calling a clearing closure on it.** `~ x xs { ( f xs ) … x … }`, with `f` a closure that clears its Vec parameter, is not refused. The loop's container check asks the closure's summary before the module has compiled, and it isn't final until then. Reading `x` after the clear is a heap-use-after-free. Until the fix ships, don't change the iterated Vec through a closure inside its own loop.
