**agora #706: a `HashMap` whose values are closures, grown.** `( map_set [i ( @ i )] m k \ → i { … } … )` is accepted, and from the sixth entry on — whenever the table grows — every closure the rehash moves is left behind: `__map_grow` reads each value into a binding and stores the binding, which for a closure clones its environment, so the new slot holds a copy and the environment in the old buffer is never released. A leak, not a fault; no panic is involved. A `Deque` or a `BTree` of closures moves them slot to slot and is clean. Until the fix ships, size the map once with `map_with_cap` so that it does not grow, or keep the closures in a `Vec` and the map's values as indices into it.
