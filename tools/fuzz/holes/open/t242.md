**agora #242: a closure bound by `:` from a join or a value block and then
handed on by name.** Its elaborated twins are closed:
- a `:` binding of a join takes the owner its arm selects, and keeps how deep
  what its other arms lend lives, so handed to an outer binding it is copied
  there or refused (AGORA-953);
- a non-copyable one handed back is refused where its join's calls lend this
  frame's values (AGORA-953);
- a value block's raw view of its own local gets a copy, and `= a g` with g a
  second name of a's own env releases nothing (AGORA-953);
- an `inout` parameter takes a binding owned per path, and a block ending in
  a fresh call owns its result;
- a value a `;` defer reads or releases is refused, and so is a `:` join's
  arm reading a field of an inner block's struct, assigned outward
  (AGORA-941);
- a by-pointer capture given by name a binding of a join of the closure's
  locals' lends, or of its own value, is copied in where it lent (AGORA-961).

Still faulting: a `??` of closures over a local option's payload, bound and
handed back (AGORA-958, github#2199, in the queue).

Also open: a mutable raw string binding of such a block, `: ~ s e { : String
x … ( string_data x ) }` then `^ e` (tools/ncore/openprobes), which the `: ~ s`
let path does not copy in as the `:` one now does.

Until #222 closes them: hand a `??` of closures back directly (`^ ?? o {
… }`), which copies the payload into the closure, instead of through a
binding; and give a raw string block's value an immutable binding (`: s e {
… }`), which is copied.
