**agora #383: a callee that leaves one argument viewing another's
elements.** `@ put ( Vec String ) arena ( Vec s ) idx String key → v {
… : String e ( vec_at [String] arena n )  ( vec_push [s] idx ( string_data
e ) ) }`: the callee's answer has no pair for a view of an argument's
elements' buffers, so the caller ties `idx` to nothing, and clearing
`arena` afterwards (`vec_clear`, `vec_pop`, `vec_truncate`) leaves `idx`
viewing freed bytes. The same holds for a closure over such an element
that the callee stores into an `inout` holder where the store cannot copy
the element in (a `Vec` of values with a `% Drop` of their own): the
answer has no pair for the closure's copy of the element's handle either.
Until the fix ships, don't drop a Vec's elements while another container
holds views of them, or keep both in one owner that drops them together.
