**agora #713: a closure handed to a function that runs it on several threads.** A function that spawns more than one thread with its closure parameter — `stdlib/std/par.nu`'s `par_map_index`, or a helper of the program's own with `thread_spawn` in a loop — asks the closure it is handed only whether its captures may MOVE to another thread (Send). They do not move: every spawned thread runs the one closure, so a capture it changes is changed by all of them at once — `( par_map_index [i] 20000 8 \ i k → i { ( vec_push [i] seen k ) ^ k } )` grows one plain `Vec` on eight threads (a double free). The same closure kept in an `Arc` and run by several threads is refused. Until the fix ships, a closure given to `par_map_index` (or to any function that runs it on more than one thread) must only read what it captured, or reach shared state through a `Locked`, an `Atomic` or a `Channel`.
