**agora #795: a `Locked` of a `% Drop` value taken out with `locked_take`
and never restored, its last share then dropped.** `locked_take`
(stdlib/std/thread.nu) moves the value out and leaves zero bytes in the
lock's slot, but nothing the drop reads marks the slot as taken, so the
last `Locked_drop` runs the value's destructor a second time, on the zeros:
a destructor that reads a field sees `0` (the value it ran on first was
the taker's), and one that writes through a field faults. `rc_take` /
`rc_restore` (stdlib/std/rc.nu) share the design: `Rc_drop` drops the
value slot without looking at `RC_TAKEN`, so an `Rc` of a `% Drop` value
taken and not restored does the same, and so do the library handles that
check their state out through them (`compiler/tests/handle_checkout.nu`). The formal model
(`formal/CLAIM.md`, `Locked D`) frees a taken block with no code and runs
the destructor once, on the taker; the runtime must match it. Until the fix
ships, restore every value taken out of a `Locked` or an `Rc` of a `% Drop`
type before its last share goes (`locked_update` instead of
`locked_take` where the value need not leave the lock).
