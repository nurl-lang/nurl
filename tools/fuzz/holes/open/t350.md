**agora #350: a change through a `~ e vv` loop's element, made by a callee.** A function that changes its own loop element over a parameter (`@ grow ( Vec String ) v → v { ~ x v { ( string_push_str x … ) } }`) records no summary of the change, so a caller's view of an element's contents taken before `( grow vv )` is read after the change freed it. The same change written in the caller's own loop is refused. Until the fix ships, do not keep a view of an element's contents across a call that changes the elements through a loop.
