# NURL Development Roadmap

This roadmap outlines the planned development for the NURL (Neural Unified Representation Language) project. Tasks are categorized and prioritized to evolve NURL into a robust, high-performance, and LLM-friendly systems language.

## Status (May 2026)
NURL has achieved a stable self-hosted compiler (Grammar v2.0) targeting LLVM. It features single-owner memory management with auto-drop, a functional standard library (JSON, HTTP client/server, Crypto, Threads/Mutex/Cond, Channels, Regex, MCP, Anthropic Claude API), and supports native (Linux/Win/macOS) and WebAssembly targets. **HTTP server stack:** Phases 1–6 + 5.3 (thread pool) + 5.4 (keep-alive, ~38× speedup on hot endpoints) + 5.4.1 (pipelining-correct framing — both requests of a same-`send()` pipelined pair reach the handler with intact bodies) + 7 (mime/static/auth/cookies/form) + 8 complete (access log, Prometheus metrics, idle timeout, graceful-shutdown via SIGINT/SIGTERM/Ctrl+C, per-request total timeout, configurable parser limits, **handler panic recovery** via the new `stdlib/std/panic.nu` model) + 9 mostly (multipart/form-data file uploads + reverse-proxy / streaming pass-through for AI gateways + **TLS** via server-side libssl/OpenSSL with TLS 1.2 minimum) shipped; Phase 9 leftovers (HTTP/2, WebSocket) remain, plus TLS extras (SNI, ALPN, client-cert auth, session resumption tuning) deferred for v2. **Variadic FFI (v1.9):** `printf`-family directly callable via the new `...` FFI marker — `gen_call` auto-promotes `float → double` and narrow ints → `i32` per ISO C §6.5.2.2; closes the last documented compiler bug in `docs/GOTCHAS.md`.

## 1. Core Language & Compiler
Enhancing the type system and compiler efficiency.

- [x] **Visibility Control — extended to structs/enums/consts 2026-05-15:** `pub` enforcement now covers struct/enum type declarations and global constants in addition to `@`-functions. New helpers `vis_record_type` / `vis_record_const` mirror `vis_record_fn`'s shape; enum variants inherit the parent enum's visibility (the per-variant globals get `vis_record_const` with the same flag). Enforcement at parse_type_base (any `%Name` resolution checks `vis_check_xref`) and gen_ident (every `__global` lookup checks the same). FFI and trait/impl decls accept the `pub` prefix forward-compat but do not enforce — FFI symbols are linker-level ABI globals, trait dispatch is type-driven through method mangling. v2.1 ships every prerequisite the package manager (§4) needs: a defined public API surface for fns, types, consts. Regressions: `compiler/tests/pub_type_visibility.nu` (positive — pub struct + pub enum + pub const used across files), `should_fail_pub_type_neg.nu` / `should_fail_pub_const_neg.nu` / `should_fail_pub_variant_neg.nu` (negatives, COMPILE FAIL), shared `should_fail_pub_type_helper.nu`. Bootstrap fixed point holds (stage1 ≡ stage2 byte-identical IR at 1 160 779 B, +8 993 B vs Tier-E ship — covers `vis_record_type` / `vis_record_const` / `vis_check_xref` helpers, four decl-handler hookups, parse_type_base + gen_ident enforcement sites).
- [x] **Visibility Control — shipped 2026-05-14 (Grammar v2.0):** New reserved keyword `pub` (`LTT_PUB = 44` in `stdlib/runtime.c`) marks a top-level decl public. Per-file strict-vis mode is OPT-IN — a source file enters strict mode the first time any of its decls carries `pub`. In strict mode, every unmarked `@`-function is private to that file; calls from another file are rejected with `private function 'X' is not visible across files; defined in 'Y'`. Files with no `pub` decls stay in legacy mode — the entire existing stdlib + test corpus continues to build unchanged. `compiler/nurlc.nu` tracks per-fn origin + per-file strict-mode in a new `g_vis_syms` map; the current source file is saved/restored across nested `$`-imports; `gen_call` enforces the rule at @-fn dispatch sites. Forward-compat parse paths for `pub` on `:` / `&` / `%` decls accept the prefix but do not yet enforce — wider enforcement (types, traits, FFI symbols) is the next pass. `nurlfmt` glues `pub` onto the following decl-starter so `pub @ greet` stays on one line through the formatter. Regression: `compiler/tests/pub_visibility.nu` (positive) + `compiler/tests/should_fail_pub_visibility_neg.nu` (negative, expected COMPILE FAIL) + `compiler/tests/should_fail_pub_helper.nu` (shared helper module). Bootstrap fixed point holds (stage1 ≡ stage2 byte-identical IR); 267-file nurlfmt round-trip sweep passes with byte-identical LLVM IR. Grammar snapshot: [`spec/grammar_v2.0.ebnf`](spec/grammar_v2.0.ebnf). **Strategic value:** package management (§4) needs a defined public API surface — `pub` is the prerequisite.
- [x] **Fixed-Size Types — shipped 2026-05-14 (Phases 1A + 1B):** Lexer recognises `i8`, `i16`, `i32`, `u16`, `u32`, `u64`, `f32` as multi-char TYPE_KW tokens (grammar v1.8). LLVM mappings: i8/i16/i32 → iN, u16/u32 → i16/i32 with signedness in a per-binding `__nurl_type` + `__unsigned` side-channel, u64 → i64, f32 → float.
  - **Phase 1A — declarations + casts + stores:** `gen_cast` chooses `sext` vs `zext` from the binding's `__unsigned` flag for widening, `trunc` for narrowing; float ↔ double uses `fpext` / `fptrunc`, mixed float/double covered by `fptosi` / `sitofp`. `coerce_store_val` applies the same width-adjustment on store, so `: i32 width  ( fn → i32 )` and similar narrow-result bindings now store cleanly without manual `# T` casts. `binop_instr`'s `isf` predicate recognises both `double` and `float` so f32 arithmetic emits `fadd` / `fsub` / `fmul` / `fdiv`. Regression: `compiler/tests/fixed_size_types.nu`. Bootstrap fixed point at 1 112 250 B.
  - **Phase 1B — unsigned arithmetic:** `gen_ident` writes the loaded binding's `__unsigned` flag into a `__last_unsigned__` side-channel symbol; `gen_binary` snapshots the LHS marker before evaluating the RHS and selects the unsigned op family (`udiv`/`urem`/`lshr`/`icmp u*`) if either operand carries the flag. Result signedness is propagated for nested expressions. Bitwise `&` / `|` are sign-agnostic; the i64/i32-only gate in `gen_logical_or_bitwise_and` / `_or` was broadened to all integer widths so sized integer operands compose with `&` / `|` without an explicit cast. Regression: `compiler/tests/unsigned_arith.nu` (udiv/urem/lshr/icmp ult vs slt on high-bit-set u32; u16 + u64 paths; i16 bitwise; nested unsigned propagation). Bootstrap fixed point at 1 113 859 B (+1 609 B vs 1A). Remaining v1.8 gap: variadic FFI does not yet auto-promote `f32` → `double` or narrow ints → `int` — declare FFI signatures with the platform's exact ABI types.
- [ ] **Tail-Call Optimization:** Implement `musttail` support for deep recursion optimization.
- [x] **Variadic Functions — shipped 2026-05-14 (Grammar v1.9):** FFI declarations may end the param list with the literal `...` token (new `LTT_ELLIPSIS = 43` in `stdlib/runtime.c`). `gen_ffi_decl` records `<fname>__variadic` / `<fname>__variadic_fixed` side-channels; `gen_call` consults them and applies the C default argument promotions (ISO C §6.5.2.2) to every arg beyond the fixed count — `float → double` via `fpext`, narrow ints (`i1` / `i8` / `i16`, signedness from the binding's `__unsigned` flag) → `i32` via `sext` / `zext`. `i32` / `i64` / `double` / pointers pass through unchanged. Unlocks `printf` / `snprintf` / `fprintf` / `scanf` family from NURL without per-call hand-widening; closes `docs/GOTCHAS.md` §9 (the only remaining real bug in that doc — every other §1-10 entry is an intentional design choice). Regression: `compiler/tests/variadic_ffi.nu` (i8/u/i16/u16/i32/u32/f32/i64/s all in one printf call, +bool→i32, +nested arithmetic promotion). Bootstrap fixed point holds at 1 125 285 B (+11 426 B vs Phase 1B). nurlfmt round-trips `...` as a single OP token (added 6b branch in `tools/nurlfmt/tokenize.nu`).
- [x] **Int-literal match arms — shipped 2026-05-18:** `gen_match` accepts `TT_INT` as an arm pattern (`?? n { 1 → ... 42 → ... _ → ... }`). Emits a single `icmp eq <match_type>` per arm and branches to the matching body. Skips enum-variant lookup, payload binding, and exhaustiveness tracking — a wildcard arm is required to cover the residual. Works for any integer match type (i, i8/16/32/64, u/u16/u32/u64). Replaces ~280 lines of `? == x N { ^ Y } {}` cascade in `stdlib/ext/http2_hpack.nu`'s static-table + Huffman-lookup tables with the natural match syntax. Regression: `compiler/tests/match_int_literal.nu` (positive / zero / large / negative literals + i32 sized match-value). Bootstrap fixed point holds.
- [ ] **Forward References:** Support forward references for enum variants.
- [ ] **Async/Await Design:** Design and implement an asynchronous programming model (Coroutines vs. Async/Await).
- [ ] **Type Conversions:** Expand support for `zext`, `sext`, and `trunc` for all sized types.
- [ ] **Compiler-Embedded LLM:** Integrate LLM-driven suggestions for self-correcting compile errors.
- [x] **Multi-field Result Ok arm (`! T E`) — shipped 2026-05-14:** Multi-field T is heap-boxed at construction (`gen_agg_lit`), unboxed at `??` match (`gen_match`) and `\` try-propagate (`gen_try_expr`). Closes `docs/GOTCHAS.md` §6 — the tagged-struct `ParsedHead { head, consumed, ok, err }` workaround in `stdlib/ext/http_request.nu` and the deferred buffered path in `stdlib/ext/http_proxy.nu` can now move to a native `! T E` signature. Regression: `compiler/tests/result_multifield.nu` (construct + `??`) + `compiler/tests/result_multifield_try.nu` (chained `\`). Unblocks: `Vec[Header]` typed input on `http_request`, buffered `! HttpResponse HttpErr` proxy path, and the mirror fix for multi-field Option Some-arm below.
- [x] **Multi-field Option Some arm — shipped 2026-05-14:** Investigation showed the natural `{ i1, %T }` Option layout already round-trips multi-field T correctly through construction (`@ ? T { T v }`), `??` destructure, and `\` propagate — Option keeps the inline payload because the slot is typed (unlike `! T E`'s uniform i64 slot which needs heap-boxing). The single failure mode was the `# T 0` dummy-zero idiom (`@ ? T { F # T 0 }` in `vec_get`, `hashmap_get`, and `stdlib/std/iter.nu`): when T's f0 was a non-pointer named type (`%String` inside `Header`, `%Vec__u` inside `MultipartPart`), `gen_cast` emitted `insertvalue %Header undef, i64 0, 0` which LLVM rejected as a type mismatch. **Fix:** `gen_cast`'s `i64 → struct/enum` branch now returns `zeroinitializer` when f0 is neither pointer nor `i64`, servicing the standard None-payload idiom uniformly. Closes `docs/GOTCHAS.md` §4. Regression: `compiler/tests/option_multifield.nu` (Pt2 / Quad / Tagged with %String f0 — incl. `vec_get [Tagged]` in-range + OOB) and `compiler/tests/option_multifield_try.nu` (`\` propagate). Bootstrap fixed point holds (stage1 ≡ stage2 at 1 068 160 B, +1 352 B / +0.13 % over the pre-fix `! T E` heap-box ship). Unblocks `Vec[Header]` for `http_request` and any future stdlib that depends on a working `vec_get [MultiField]`.
- [x] **Generic propagation through nested structs — shipped 2026-05-17 (unblocks `Channel[A]`, `Vec[Thread]`):** Two compiler additions to `emit_one_instantiation` + `ensure_struct_instantiated` now propagate generic-struct instantiation through (a) generic-function bodies that reference inner generic structs, and (b) generic-struct field types that reference further generic structs. **The fix:** when monomorphising a generic function with `T → Concrete`, the compiler re-scans the substituted source so any `( Inner Concrete )` triggers `ensure_struct_instantiated` before the body is parsed; symmetrically, when a generic struct body is materialised (e.g. `( Wrap s )` whose body is `{ ( Vec s ) items, i flag }`), the substituted body is re-scanned so `( Vec s )` is emitted first — otherwise LLVM resolves the inner type as opaque and downstream `getelementptr` on the outer aggregate fails with "base element must be sized". Result: two generic structs side-by-side now compose freely; `Channel[A]`'s old `ChannelImpl[A] { Mutex, Cond, ( Vec A ) q, … }` shape compiles. **`stdlib/std/channel.nu` rewritten as `Channel[A]` / `chan_new [A]` / `chan_send [A] ( Channel A ) ch A v` etc.** — `[i]` instantiation is the migration path for the existing i64-channel callers (one update site: `compiler/tests/channel_basic.nu`). `[s]` confirmed working in the regression test, as is `Vec[Thread]` (manually verified — Thread is a single-pointer handle so it composes through Vec via the standard generic-struct path). Regression: `compiler/tests/generic_nested_struct.nu` (Inner/Outer + Wrap/Vec cases). Bootstrap fixed point holds (stage1 ≡ stage2 byte-identical IR at 1 187 843 B, +3 377 B vs PostgreSQL ship — covers the two new re-scan call sites). **Still separate work:** passing an anonymous closure type `( @ v )` as a generic-function type arg (the `[ ( @ v ) ]` form) — that's its own codepath, not name-resolved through `g_generic_struct_syms`.
- [x] **Multi-field struct mutability — shipped 2026-05-14:** Two-part fix.
  - **Part A (closures):** `: ~` opts a binding into mutability AND, for multi-field structs, into closure capture-by-pointer. The env block stores the caller's alloca pointer as `T*` instead of snapshotting the value; the closure body registers that pointer as the binding's `__ptr` so every `= . c field val` and `. c field` reaches the shared alloca. Immutable captures (`: Counter c …`) keep the snapshot semantics — backward-compatible. Single-pointer-handle structs (`%String`, `%Vec__T`) and enums fall through unchanged. New helper `__is_capture_byref` gates the three touch points (`gen_env_struct_type`, `gen_env_allocation`, closure-body capture extraction in `gen_closure_expr`). Lifetime caveat: capturing by pointer means the closure borrows the caller's stack alloca — escaping closures must still use a heap-backed handle pattern (e.g. `( Vec i )` backing like `stdlib/ext/http_middleware.nu`'s `Metrics`). Regression: `compiler/tests/multifield_struct_mut.nu`.
  - **Part B (function parameters):** `= . p field val` on a struct parameter previously emitted invalid IR (empty GEP base) because `gen_fn_param` never backed the parameter with an alloca. `gen_fn_decl_concrete` now invokes `__alloca_struct_params` right after the `entry:` label; it walks the param roster collected by `gen_fn_param` (under `__fn_params__`) and emits `alloca + store + __ptr` for every multi-field-struct parameter. Value semantics intact — the function mutates a local copy, the caller's binding is unchanged. Canonical share-mutation pattern: return the modified struct (`= c ( f c )`). Regression: `compiler/tests/function_param_mut.nu`.
  - Closes `docs/GOTCHAS.md` §2 (both halves). Bootstrap fixed point holds (stage1 ≡ stage2 at 1 090 251 B, +19 289 B vs pre-fix; the two regression tests + alloca emission account for the increase).
- [x] **Mutable enum bindings — shipped 2026-05-14:** `coerce_store_val` now wraps `i64 → %Enum` with `insertvalue %Enum undef, i64 val, 0` before store, detected via the `<name>__variants` side-table registered by `gen_enum_decl`. Fixes both `: ~ NetErr last_err NetOther` (mutable, originally documented) and the symmetric immutable case `: NetErr e NetOther` (equally broken but undocumented). Works for narrow enums and wide enums (tag-only variants via bare name; payload-carrying variants still go through `@ Foo { Variant payload }`). Closes `docs/GOTCHAS.md` §3. Regression: `compiler/tests/mutable_enum_binding.nu` (narrow + wide + http_server-style sentinel pattern). Bootstrap fixed point holds (stage1 ≡ stage2 at 1 070 962 B, +2 802 B vs prior). Unblocks (and in the same commit refactors) the `had_err: b` sentinel-flag dance in `stdlib/ext/http_server.nu` `server_run` — it now carries the failing variant directly through `: ~ NetErr last_err NetClosed` instead of re-issuing `server_run_once` to recover the variant.

## 2. Standard Library (Tier 3-5)
Rounding out the standard library for production use.

### Data & Filesystem
- [x] **SQLite FFI — shipped 2026-05-15:** `stdlib/ext/sqlite.nu`. Thin wrapper over libsqlite3 with idiomatic `! T SqliteErr` returns. Surface: `sqlite_open / _close / _exec / _prepare / _bind_int / _bind_text / _bind_null / _step / _column_count / _column_int / _column_text / _column_type / _reset / _finalize`. `:memory:` and file-based connections; in-process only (no networking). MVP scope deliberately narrow: no BLOB / double / transaction helpers / statement cache / ATTACH / WAL tuning — callers compose those with SQL or with the existing primitives. Build-time dep detected via `pkg-config --exists sqlite3` (mirrors libcurl / openssl pattern); without it every call returns `SqliteUnsupported` at runtime. Regression: `compiler/tests/sqlite_basic.nu` (in-memory CRUD round-trip with prepared statement reuse).
- [x] **PostgreSQL FFI — shipped 2026-05-15 (pure-NURL model):** `stdlib/ext/postgres.nu` declares every libpq symbol directly via `& \`pq\` @ ... → ...` — **zero `runtime.c` changes**. Surface: `pg_connect / _close / _err_msg / _exec / _exec_params / _result_status / _result_is_ok / _ntuples / _nfields / _get_value / _get_is_null / _field_name / _clear`. Connection / PgResult value handles wrap raw `s` pointers. `pg_exec_params` builds a parallel `char *` array from a `Vec[String]` and passes it as the libpq parameter pointer. Build-time dep detected via `pkg-config --exists libpq` (mirrors libcurl / openssl / sqlite3 patterns). Regression: `compiler/tests/postgres_basic.nu` (NURL_PG_TESTS=1 + PG_CONNINFO=... to enable; default prints the skip notice). **First example of the pure-NURL FFI model** — future stdlib bindings should default to this shape unless they need runtime-level state caching that NURL can't express idiomatically (sqlite3's `column_text` snapshot or `bind_text` TRANSIENT-flag bookkeeping).
- [ ] **Advanced Filesystem Ops:** Recursive directory creation/removal (`dir_create_all`, `dir_remove_all`), file handles for chunked reading (`file_read_chunk h n`, `file_readline h`).
- [ ] **Serialization (Serde):** General-purpose `Serialize[T]` and `Deserialize[T]` traits for JSON, MsgPack, and TOML.
- [x] **Compression — shipped 2026-05-17 (zlib + zstd + gzip):** `stdlib/ext/compress.nu`. Pure-NURL FFI for libz (`compress2` / `uncompress` / `compressBound`) and libzstd (`ZSTD_compress` / `_decompress` / `_compressBound` / `_getFrameContentSize` / `_isError`). API: `zlib_compress` / `zlib_compress_at level` / `zlib_decompress` (auto-grow on Z_BUF_ERROR), `zstd_compress` / `zstd_compress_at level` / `zstd_decompress` (uses frame-content-size when available, else grow-fallback). `! ( Vec u ) CompressErr` returns; errors map to `CompressData` / `CompressMemory` / `CompressBufTooSmall` / `CompressOther`. Build-time pkg-config detection emits `stdlib/runtime.z` / `stdlib/runtime.zstd` sentinels for the FFI lib-check (compile-time diagnostic on missing zlib1g-dev / libzstd-dev). **Gzip wire format (RFC 1952) shipped same day:** `gzip_compress` / `gzip_compress_at` / `gzip_decompress` with byte-identical interop against the `gzip` / `gunzip` CLI tools and HTTP `Content-Encoding: gzip`. Decompress auto-detects gzip OR zlib input (libz's `inflateInit2_(windowBits=15+32)`), so a single helper handles both wire formats coming back from heterogeneous peers. The streaming API stays C-side via the thin `nurl_gzip_compress` / `nurl_gzip_decompress` bridge in `runtime.c` §22 because `z_stream`'s sizeof and layout are platform-specific (88 B on Win64, 112 B on Linux/macOS x64) — same architectural exception as the sqlite3 borrowed-view bridge. ISIZE-trailer pre-sizing avoids the grow-and-retry loop on the common path. Regressions: `compiler/tests/compress_basic.nu` (zlib/zstd round-trip + empty + garbage) + `compiler/tests/compress_gzip.nu` (gzip round-trip + magic-bytes wire check + level-0 store-only + empty + auto-detect-zlib + garbage).
- [x] **UUID Support — shipped 2026-05-08:** Implement RFC 9562 compliant UUID v4 and v7 generation, parsing, and formatting. Includes comprehensive lifecycle tests and stdlib documentation.
- [x] **Quoted CSV Support — shipped pre-2026-05-17 (roadmap-line stale; closed 2026-05-17):** `stdlib/ext/csv.nu` already implements RFC 4180 quoting via the `CSVDialect { delimiter, crlf, quote_char }` struct (`quote_char = 34` enables the quote-byte branch in both reader and writer; `csv_dialect_unquoted` disables it for known-quote-free data). The `CSVTable` arena layout stores unescaped quoted-cell bytes in a separate `escape_buf` indexed by negative offsets. The roadmap entry was a leftover from the v1 pre-arena CSV code that didn't have quoting; surfaced and removed during the 2026-05-17 critic-cleanup sweep.
- [x] **Sized Vector Slices (`Slice[A]`) — shipped 2026-05-17:** `stdlib/core/slice.nu`. Generic `Slice[A] { *A data, i len }` view type, designed to replace `vec_data` + manual index arithmetic in hot loops. Constructors `slice_from_vec` / `slice_sub` (clamped half-open `[from, to)`, None if `from > to` after clamping) / `slice_from_raw`. Inspectors `slice_len` / `slice_is_empty` / `slice_data` / `slice_get` (bounds-checked, returns `?A`) / `slice_first` / `slice_last`. Lifetime is borrow-style: a Slice is valid only while its backing storage exists and unchanged in capacity — the compiler does not check, same discipline as a C pointer-into-buffer. Regression: `compiler/tests/slice_basic.nu`.
- [x] **Calendar Time API — shipped 2026-05-06:** `Time { year, month, day, hour, min, sec, ns, wday }` struct + `time_from_unix` / `time_to_unix` (Howard Hinnant's `civil_from_days` / `days_from_civil` algorithms — proleptic Gregorian, branch-free, full i64 range), `time_now`, `time_format_iso` (`2026-05-06T17:30:45Z`), `time_format_http` (RFC 7231 IMF-fixdate `Wed, 06 May 2026 17:30:45 GMT`), `time_parse_iso → ! Time ParseErr` (offsets `+HH:MM`/`-HH:MM`/`Z`/`z`, fractional seconds ignored). UTC only — no timezone/DST handling.
- [x] **Arena Allocator — shipped 2026-05-17:** `stdlib/std/arena.nu`. Single-buffer bump-pointer allocator over an opaque `Arena { s ctl }` handle (same pattern as `Channel` / `String`) so passing by value copies the 8-byte handle and every copy shares the same `ArenaImpl { *u data, i used, i cap }`. Surface: `arena_new` / `arena_with_cap` / `arena_alloc` (8-byte-aligned, NULL on OOM — caller checks) / `arena_alloc_aligned` (caller-chosen power-of-two alignment for SIMD or byte-tight) / `arena_used` / `arena_cap` / `arena_remaining` / `arena_reset` (rewind to empty, keep buffer, invalidates every outstanding pointer) / `arena_free`. v1 intentional scope: no automatic growth — `arena_alloc` returns NULL on overflow, callers either pre-size with `arena_with_cap` or chain multiple arenas. Future work: chained-chunk arena (linked list of buffers; preserves pointer validity across growth) and a generic `arena_alloc_n [T] arena count → *T` typed wrapper. Regression: `compiler/tests/arena_basic.nu` (round-trip + alignment + OOM + reset-reuse + 16-byte aligned alloc).
- [ ] **Extended Hash Family:** `sha512`, `blake3`, `md5`, `hmac_sha512` via libsodium-FFI or self-contained impl.
- [x] **Bytes Endianness — shipped 2026-05-17:** `stdlib/std/bytes.nu` gained `bytes_read_u16_be / _le`, `bytes_read_u32_be / _le`, `bytes_read_u64_be / _le` (all return `?T` — None on negative offset OR `off + N > len`), plus symmetric `bytes_push_u16/u32/u64_be/_le` writers that append the N bytes in the chosen order. Depends on the v1.8 sized unsigned types (`u16`/`u32`/`u64`). **Compiler fix bundled:** `gen_member`'s raw-pointer load paths now snapshot `__last_unsigned__` before parsing the index expression and restore it after the load, so a `# i ( . p k )` cast over a `*u` element emits `zext i8 → i64` (not `sext`) regardless of whether the index is a literal or a variable. Without this, high-bit-set bytes (0x80–0xFF) sign-extended to `0xFFFF…FF80–FF` and corrupted shift-and-add accumulators — discovered while writing this module, fixed at the compiler level so future binary-protocol code doesn't need explicit `& 255` masking. Unblocks: gzip CRC-32 + ISIZE trailers (RFC 1952), MessagePack header bytes, BSON length prefixes, network packet headers — every binary protocol that needs explicit byte order. Regression: `compiler/tests/bytes_endian.nu` (all 12 functions, boundary values incl. u16 0xFFFF / u32 0x80000001 / u64 0x0123456789ABCDEF, byte-layout sanity per direction, OOB + negative-offset return None). Bootstrap fixed point holds (stage1 ≡ stage2 byte-identical IR at 1 188 666 B, +823 B vs the generic-propagation ship — covers the two-line snapshot/restore in `gen_member`).
- [ ] **Structured Logging:** `log_info_kv` for key-value pairs, JSON output mode for log lines.
- [ ] **Typed Path:** `Path { String inner }` type with `path_canonical` (via `realpath`) and `path_relative_to base`.

*Previously: May 15, 2026 — **Panic model + handler panic recovery shipped.** Closes Phase 8 end-to-end and unblocks the last Tier B item (#4 in the critic.md follow-up list). The model is deliberately narrow: explicit `panic` + setjmp/longjmp-based `recover`, NOT Rust-style stack unwinding with destructor calls.

**New module `stdlib/std/panic.nu`.** Two surface forms:
- `panic s msg → v` — Halts execution. If a `recover` frame is active on this thread, longjmps to it; the matching `recover` returns Err with `msg` captured in `PanicInfo.msg`. Otherwise prints to stderr and aborts (status-quo for unrecoverable conditions).
- `recover ( @ v ) closure → ! v PanicInfo` — Runs the closure under a setjmp guard. Returns Ok(0) if it completed normally, Err(PanicInfo) if it called `panic`. Closure must return void; for typed results, capture a `: ~`-mutable multi-field struct by-ref (existing byref-capture path) and write to it inside the closure.

**Runtime (`stdlib/runtime.c` §20).** Three new entry points:
- `nurl_recover(void *fn_ptr, void *env_ptr) → long long` — pushes a `NurlPanicFrame` on the thread-local stack, setjmps, calls `fn_ptr(env_ptr)`, returns 0 on normal completion or 1 if a panic longjmped back.
- `nurl_panic(const char *msg)` — writes msg to top frame, longjmps; aborts if no frame.
- `nurl_panic_last_msg(void) → const char*` — borrowed view of the captured message slot. NURL `recover` copies via `string_from` since the slot is owned by the runtime and overwritten on the next panic.

Frames live on the C stack of the `nurl_recover` invocation. Thread-local storage via `__thread` (Clang/GCC) — works on Linux, macOS, mingw-w64; degrades to a global on single-threaded WASI.

**Cost model (documented up-front):**
- Owned heap allocations made inside a recover scope that don't run their auto-drop **LEAK**. setjmp/longjmp can't run destructors; the auto-drop machinery isn't involved. Recover is crash-mitigation, NOT a routine error path — always prefer `! T E` + `\` for expected errors.
- SIGSEGV / SIGFPE / SIGBUS / SIGABRT are **NOT caught**. Signal faults remain process-aborts. Async-signal-safety on POSIX would force every runtime function into a "may run during signal" contract that's both onerous and easy to break. Signals are out of scope.
- For HTTP server use: per-handler-panic leak is bounded by per-request scratch state (typically a few hundred bytes); the worker thread keeps running so the *process* survives. A net win vs aborting the worker.

**Compiler tweak — `simple_capture_analysis` now captures assignment targets.** Pre-fix bug: `= resp val` inside a closure body where `resp` is an outer mutable local performed the mutability check but did NOT add `resp` to `captured_vars`. The closure body then referenced the outer's alloca register directly (`store … %r49`), producing invalid IR (undefined value). Detected by `compiler/tests/http_proxy.nu` linking failure on the HTTP-server panic-recovery integration. Fix: the assignment branch in `simple_capture_analysis` now appends `target_var` to `captured_vars` the same way the read-side branch does for outer locals that aren't closure params. Zero false positives — the fix only adds names that the body actually references; pre-fix code never relied on writes-without-captures because that path was already broken.

**HTTP server integration.** `__serve_keepalive_loop` declares `: ~ HttpResponse resp ( response_text 500 "internal server error\n" )` as the default, then runs the handler under `recover \ → v { = resp ( f req ) }`. On Err arm, the captured panic message is logged via `nurl_eprintln "[panic] HTTP handler: <msg>"`; `resp` keeps the default 500 because the assignment never fired. On Ok arm, `resp` carries the handler's return value. The byref-capture of `resp` (multi-field struct + `: ~`) routes the assignment through the env block's pointer back to the outer alloca — exactly the pattern the v2.1 closure-byref capture path was built for.

*Previously: May 15, 2026 — **HTTP server pipelining correctness shipped.** The keep-alive request loop in `stdlib/ext/http_server.nu` previously allocated a fresh `Vec[u]` per `__read_request_head` call and copied any bytes past the parsed head wholesale into `req.body` (lines 168-179, pre-fix).
