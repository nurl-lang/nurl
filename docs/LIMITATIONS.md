# Known Limitations

Limitations of the **language and the compiler** (`compiler/nurlc.nu`) — the
fixed rules a program must work within. The authoritative grammar is
[`spec/grammar.ebnf`](../spec/grammar.ebnf); the normative language reference
is [`docs/spec.md`](spec.md).

This page is deliberately scoped to language + compiler. Standard-library
feature coverage and gaps (databases, TLS, MQTT, …) are *not* language
limitations — they live with each module (the `stdlib/**` file headers and
[`docs/NETWORKING.md`](NETWORKING.md)) and on the [`ROADMAP.md`](../ROADMAP.md).

**31 soundness holes are known open** ([`MEMORY.md` �6.2](MEMORY.md)).
Each is a use of freed or moved-out memory in safe code, with a fix in progress:

- **agora #242: a join or a value block bound by `:` and then handed on
  by name, in nine remaining shapes.** The common ones are closed: a `:`
  binding of a join takes the owner its arm selects, an `inout` parameter
  takes a binding owned per path, a block ending in a fresh call owns its
  result. Nine shapes still fault, each the elaborated twin of a closed
  probe ([`twins.txt`](twins.txt)): the binding does not inherit what its
  producer lends — a call in an arm lending a local, a field or a view of
  an inner local, a value a `;` defer releases. Until #222 closes them,
  hand such a value on directly (`^ ? c a b`) instead of through a binding.
- **agora #280: a field a `sink` took, used again by a route the
  check does not see.** A field a `sink` took (`( take . h buf )`) is refused
  while it is empty when it is read, bound, handed on whole with `h`, or
  left empty at an `inout` exit. These are still accepted, and run into the
  null handle or freed memory: a take inside a loop, read on the next round;
  the taken field handed back itself (`^ . h buf`, `^ @ Holder { . h buf }`,
  `= h @ Holder { . h buf }`); a path under or over the taken one (`. o a`
  taken, then `. . o a b` read, or the reverse); `h` handed on whole by
  `^ @ Outer { h }`, `^ ? c h h2`, `= h2 h`, a value block `{ h }` or
  `= . g buf . h buf`; a closure made after the take, `h` captured and
  returned, or a closure's own `inout` parameter; a `% Drop` destructor that
  reads the taken field; and an `inout` callee that panics between the take
  and its refill, caught by a `recover` closure that captured the struct.
  Until the fix ships, give the field a value right after the take
  (`= . h buf ( vec_new [u] )`), or hand the callee a copy
  (`( mem_dup . h buf )`) and keep the field.
- **agora #292: a view pushed into a vector through a borrow of it is not
  recorded on the owner.** `: ( Vec ( Slice u ) ) w ( id vs )` (or a field
  viewer `. o kids`, or an element borrow `( vec_at … vs 0 )`), then `(
  vec_push [( Slice u )] w ( slice_from_vec [u] loc ) )` with `loc` a
  block's local: after the block, a read of the slice through `vs` reads
  `loc`'s freed bytes. Pushed through the owner's own name it is refused.
  Until the fix ships, push views into a vector only through its owner, by
  name.
- **agora #293: an owner's buffer moved through a copy of its handle
  leaves a slice of it live.** `: ( Slice i ) sl ( slice_from_vec [i] vs
  )`, then `: ( Vec i ) w ( id vs )` (or a field viewer `. o buf`) and `(
  vec_reserve [i] w 4096 )`, or pushes through `w`: `sl` still points into
  the buffer that moved. Through `vs` itself it is refused. Until the fix
  ships, grow or reserve a Vec only by its owner's own name while a slice
  of it is live.
- **agora #294: a struct built from an owner and a view of it views its
  own buffer.** `: ( Slice u ) sv ( slice_from_vec [u] b )` then `: S o @
  S { sv b }`: growing or replacing `. o buf` (`( vec_reserve [u] . o buf
  4096 )`, `= . o buf …`) leaves `. o v` pointing into the old buffer, and
  a String field grown by `string_push_str` does the same. Until the fix
  ships, never put an owner and a view of it into the same struct.
- **agora #332: a view a closure gives a capture through a local, or a
  push into a plain Vec parameter.** Inside a closure body, a local bound
  from the closure's own parameter or from a view capture (`: ( @ v s ) setw
  \ s p → v { : s t p = w @ V { t } }`) is not followed to what it points
  into, so storing the local into a capture (whole, by field, by push, or
  into the closure's own `inout` parameter) is accepted. And a closure's
  plain `( Vec s )` parameter is no target, so `\ ( Vec s ) out → v { (
  vec_push [s] out ( string_data b ) ) }` is accepted too. When what the view
  points into ends before the capture or the caller's Vec is read, that read
  is of freed memory. Until the fix ships, give the view through a function's
  `inout` parameter, passing the view itself (`s v`), not from a closure.
- **agora #333: a callee that clears inside its parameter's elements.**
  `@ clear_first ( Vec ( Vec String ) ) p → v { ( vec_clear [String] (
  vec_at [( Vec String )] p 0 ) ) }`, or the same through a local element
  borrow or on a field of an element: the call ends none of the caller's
  borrows of that element's contents, so reading one after the call reads
  freed memory. (A callee that grows such an element is followed since
  agora #315.) Until the fix ships, take such a borrow again after the call
  instead of holding it across it.
- **agora #336: an `inout` holder given whole a view of a callee's own
  local, when the callee leaves by `^`.** `@ fill inout W w → i { : String
  b ( string_from … ) = w @ W { ( string_data b ) } ^ 0 }`: the caller's
  `w` points into `b`, which the callee freed, and a read of `. w v` after
  the call reads freed memory. The same holds for an early `^` in an arm
  and for an `inout` `?s` holder. #309 refuses the shape only where the
  callee's body ends without a `^`, and a field store (`= . w v …`) is
  refused on every path. Until the fix ships, give an `inout` holder a
  view only of what the caller passed in, or a value that owns its data
  (`string_from`).
- **agora #337: a callee that leaves a parameter other than its first
  `inout` one viewing a String argument.** `@ split inout Part head inout
  Part tail String src → v { = head @ Part { ( string_data src ) } = tail
  @ Part { ( string_data src ) } }`: the caller learns that `head` depends
  on its String, but not `tail`, so a read of `tail` after the String ends
  reads freed memory. The same holds for a Vec-of-views handle that is not
  the callee's first argument, for a callee that recurses through a local
  holder, and for a String passed `inout`. #301 ties a callee's view of a
  String parameter only to the caller's first `inout` argument, or else
  its first. Until the fix ships, give such a callee one holder of views,
  as its first `inout` parameter, and keep the String alive while the
  holder is read.
- **agora #338: an enum with a view variant is taken to hold no view.**
  The borrow check asks whether a type can hold a view, and for every enum
  it answers no (`__ty_holds_view`). So an enum whose variant is a view
  (`: | Tok { Word s Num i Bad String }`) loses its source wherever that
  question decides: returned from a function over a temporary, copied into
  a literal or a join, pushed into a Vec, stored into a field, or given to
  a closure's capture or its `inout` parameter. When the source ends
  before the enum is read, the read is of freed memory. Until the fix
  ships, keep the source of an enum's view alive as long as the enum, or
  give the variant an owned payload (`String`, not `s`).
- **agora #339: a closure called with the capture it changes.** A closure
  that assigns one of its by-reference captures (`: ( @ v String ) c \
  String p → v { = o ( same p ) }`) can be called with that capture as its
  argument, `( c o )`. Its body drops the capture's old value, which the
  argument still is, and the read after the call is of freed memory. A
  function with an `inout` parameter, called with the same binding twice,
  is refused. Until the fix ships, do not hand a closure a binding it
  assigns: pass a copy (`( string_from ( string_data o ) )`), or make the
  closure a function with an `inout` parameter.
- **agora #341: a callee that pushes a literal holding its parameter's
  view into a Vec it returns.** In `@ mk s v → ( Vec W ) { : ( Vec W ) ws (
  vec_new [W] ) ( vec_push [W] ws @ W { v } ) ^ ws }` the caller's result is
  not seen to view the argument. A source that ends first, or a younger one
  when `W` has a `% Drop`, leaves the Vec reading freed memory. A struct
  literal returned directly, and a bare `( Vec s )`, are tracked. Until the
  fix ships, build such a Vec in the caller, or keep the argument's source
  alive as long as the result.
- **agora #342: an option owner given back its own value through a
  call.** With `: ~ ?String o ( make )` and a callee that hands its
  argument back (`@ id ?String x → ?String { ^ x }`), `= o ( id o )` drops
  `o`'s old value and then stores it again, so the next read of `o` is of
  freed memory. The same with a `String` binding is right. Until the fix
  ships, do not give an option binding the result of a call that is handed
  that same binding.

  The same happens with a Vec read out of the option on the way: `: ( Vec
  Node ) w ( optkids_fwd o )  = o ( firstn_fwd w )`, with forwarders
  defined below their caller, frees the old `o` that the new `o` lives in
  (a struct's child handed back through two forwarders). Found by the #352
  adversarial pass.
- **agora #343: an `inout` option given a lend out of a borrowed Vec
  parameter.** `@ put inout ?String o ( Vec String ) vs → v { = o (
  vec_get [String] vs 0 ) }` stores the lend as it is. The caller's option
  and its Vec then both own the element, and the second release reads
  freed memory. With the Vec a local of the callee instead, the program
  does not compile: clang reports an undefined `__dropifv_w__opt.String`.
  Until the fix ships, store a copy into an `inout` option (`T (
  string_from ( string_data e ) )`), not the lend itself.
- **agora #345: a view of an Rc's state through one share, replaced
  through another.** Take a program's own handle over an `Rc` (`: X { (
  Rc Impl ) ctl }`, with `X_share` an `rc_clone`). A view of the state
  taken through one share (`rc_get` behind an accessor) is not ended when
  the state is replaced through another share (`rc_set` behind an
  accessor), so reading the view reads freed memory. Reading the `Rc`
  field directly is checked. Until the fix ships, do not keep a view of an
  Rc's state across a call that may `rc_set` it through any share; copy
  what you need first.
- **agora #346: a view parameter stored into an `inout` struct through a
  local copy.** `@ setw inout V w s p → v { : s t p = w @ V { t } }` gives
  the caller no record that `w` now views what `p` views, because the keep
  is recorded only when the stored name is the parameter itself. When the
  source ends before `w` is read, the read is of freed memory. The direct
  form `= w @ V { p }` is refused. Until the fix ships, store the parameter
  itself into the `inout` holder, not a local copy of it.
- **agora #347: copying a Vec of views with `vec_extend`, `vec_extend_range`,
  `vec_clone` or `slice_to_vec`.** These copy each element, and a copied
  view is still a view of its source. But their summaries say they keep
  nothing, so `( vec_extend [s] ws t )` or `= ws ( vec_clone [s] t )` with
  `t` holding views of a younger string leaves `ws` reading freed memory.
  `vec_append`, which moves `t`, is refused. Until the fix ships, keep the
  sources of a `( Vec s )` alive as long as every copy of it.
- **agora #348: a nested field store of a view.** `= . . h w v (
  string_data b )` records no dependency of `h` on `b`, plainly or inside
  a closure, so reading `. . h w v` after `b` ends reads freed memory. The
  one-level store `= . w v ( string_data b )` is refused. Until the fix
  ships, store a view only one field deep, or give the inner struct a new
  value whole (`= . h w @ V { ( string_data b ) }`).
- **agora #349: a buffer-moving call handed an element lent by a call.**
  `( vec_reserve [u] ( vec_at [( Vec u )] vv 0 ) 4096 )` moves the
  element's buffer, but the borrow check ends the views of `vv`'s own
  buffer instead, so a slice of that element taken before the call reads
  freed memory after it. The same call through a `:` binding of the
  element is refused. Until the fix ships, bind the element first (`: ( Vec
  u ) e ( vec_at … vv 0 )`) and grow it through that binding.

  The same move, with the element reached some other way, also leaves a
  `string_bytes` view of it reading freed memory: an element handed out by
  a program function (`( string_push_str ( first_str vs ) … )`, first_str
  defined above its caller), a `vec_get` match payload grown by a callee
  (`?? ( vec_get vs 0 ) { T e → ( grow e ) }`), a nested lend (`(
  string_push_str ( vec_at ( vec_at vv 0 ) 0 ) … )`), and a callee that
  grows an element of the Vec it was handed (`( work vs )` with `work`
  calling string_push_str on `( vec_at p 0 )`). Found by the #352
  adversarial pass.
- **agora #350: a change through a `~ e vv` loop's element.** The loop's
  element binding is not a borrow of `vv` to the borrow check, so `~ e vv {
  ( vec_clear [String] e ) }` (or a buffer move through `e`) ends no
  borrow of the element's contents, and a view of an element's contents
  taken before the loop reads freed memory after it. The same change
  through a `:` binding of the element is refused. Until the fix ships, do
  not keep a view of an element's contents across a loop that changes its
  elements.
- **agora #353: a closure that changes a capture's element through a local
  of its body.** `\ → v { : ( Vec String ) e ( vec_at [( Vec String )] vv
  0 ) ( vec_clear [String] e ) }` is not recorded as an effect of running
  the closure on `vv`, so a view of that element's contents taken before
  the call survives it and reads freed memory. The direct form `( vec_clear
  [String] ( vec_at … vv 0 ) )` in the closure is refused. Until the fix
  ships, write such a change directly on the capture's element, not
  through a local of the closure's body.
- **agora #354: two readers of one field, then the field replaced.** With
  `: String g1 . o name` and `: String g2 . o name`, replacing `. o name`
  hands the old value to both readers, so both drop it where their scope
  ends, which is a double free even when neither is read. One reader is
  right: it takes the old value over. Until the fix ships, keep at most one
  reader of a field across a replace of that field.
- **agora #357: a field of a match payload handed to a `sink`.** In `??
  ( vec_get [H] vs 0 ) { T p → ( take . p buf ) … }`, or a match of a user
  enum binding that leaves it in place, the take empties the field in the
  Vec's slot or frees what the enum still holds. A later read of the
  element is a null handle, and a second match of the enum, or its drop,
  reads freed memory. A field of a `vec_at` result is copied, and a
  `vec_at` element bound first is refused. Until the fix ships, take the
  element out whole first (`vec_remove`, a consuming match), or hand the
  `sink` a copy (`( mem_dup . p buf )`).
- **agora #358: a closure made after a borrow ended.** With `w` holding a
  view of a block-local `b`, a read of `. w v` after `b`'s block is
  refused, but a closure created after that point (`\ → v { ( nurl_println
  . w v ) }`, or a `recover` closure) captures `w` without the check, and
  calling it reads freed memory. Until the fix ships, do not capture a
  binding whose view's source has ended.
- **agora #359: a closure that changes its own parameter's contents.** A
  closure such as `\ ( Vec String ) x → v { ( vec_clear [String] x ) }`
  records no effect on its parameters, so calling it with a Vec whose
  element a caller binding still borrows leaves that binding reading freed
  memory. The same body as a function is refused at the call. Until the
  fix ships, write such a change as a function, or end the borrows of the
  argument's elements before calling the closure.

  The same goes for a closure handed to a function that calls it on the
  lent value: `( apply ( vec_at vv 0 ) \ ( Vec String ) x → v { (
  vec_clear [String] x ) } )` ends no borrow of that element, in either
  definition order. Found by the #352 adversarial pass.
- **agora #360: a `?` / `??` join whose arms are field paths.** `: ( Vec S )
  j ? == c 1 . h a . h b`, then `( vec_clear [S] j )`, or the same join as
  `vec_clear`'s argument: the join carries no source of `h.a` or `h.b`, so
  the clear ends no borrow of their elements, and a String read out of one
  of them reads freed memory after it. Until the fix ships, bind each field
  to a name first (`: ( Vec S ) a . h a`) and join the names.
- **agora #362: a callee that returns its `( Vec W )` parameter wrapped in
  a struct literal, where `W` is a `% Drop` holder of views.** `@ wrap ( Vec
  W ) ws → T1 { ^ @ T1 { ws } }`, then `= o ( wrap ws )` with `o` declared
  before the String the elements view: the caller's result is not seen to
  hold those views, so the String drops first at the end of the scope and
  `W`'s destructor reads freed memory. Built with a literal in the caller,
  `= o @ T1 { ws }`, the same value is refused. Until the fix ships, build
  a value that holds `% Drop` holders of views in the scope that owns their
  source, or declare the source before the holder.
- **agora #363: a destructor the drop check cannot see.** The check whether
  a value's drop may read a view misses three kinds of type: a type
  argument written with `?` (`( HashMap i ?W )`), a type whose own
  `S_drop` hook reads a view field, and the error side of a result (`! i
  W`). For such a value given a view of a binding declared after it, the
  younger-view refusal is skipped, and the destructor reads freed memory
  where the scope ends. Until the fix ships, declare a view's source
  before any such holder, or keep views out of types with a hand-written
  `S_drop`.
- **agora #364: an enum binding given a new value inside its own match
  arm.** In `?? o { MSome s → { = o … ( nurl_println ( string_data s ) ) }
  … }`, the assignment drops the old value, including the payload `s`
  borrows, and the read after it is of freed memory. The option form is
  refused. Until the fix ships, finish reading a match payload before
  giving its scrutinee a new value.
- **agora #366: an owner's old value whose hand-over has no key: kept
  back (a leak) on a lend path, freed under its borrower on an owned one.**
  A `: ~` owner given a new value drops its old one, and hands it to a live
  borrower that holds it instead: a `??` payload, or a `: ?T prev cur`
  cursor. That hand-over tells the old value apart by a key: a String's or a
  Vec's buffer, a record's first String or Vec field, or an enum's first
  payload where it is the value's own pointer. An option payload, a library
  handle such as a Box, a record whose first owned field is an option or an
  enum without such a key in every variant, and an enum with a variant whose
  first payload is a number or a view while a later one owns memory
  (`A i String`) have none. Given a value a call lends out of another owner
  (`= o ( vec_get [Rec] rs 0 )`), such an owner keeps its old value back and
  never releases it, as before #317's fix (agora #361 ended the
  use-after-free that dropping it caused). Given a fresh value or a `?` join
  instead (`= o ( mk )`), it still frees the old value under the borrower
  that reads it, and an option-typed alias of an option owner
  (`: ?String p ( id o )`) makes clang reject the program. Until the fix
  ships, give such an owner its new value outside the borrower's scope, or
  bind the borrower to a copy (`( mem_dup … )`).
- **agora #375: an option owner given a lend through a forwarder defined
  above its caller, with an argument that is no plain owner name.** `= o (
  nth vs 0 )`, with `nth` handing back `( vec_get vs k )` and defined above
  the caller, keeps `o`'s old value back instead of freeing it, so it leaks.
  The same happens with a field path or an alias as the argument, with the
  assignment inside a closure, and with forwarders that call each other.
  Defined below the caller, these are clean. Until the fix ships, define
  such a forwarder below its callers, or free the old value first (`= o @
  ?String { F }`).

Every other safe program found accepted and faulting is closed, and held
by a probe in [`tools/fuzz/holes/`](../tools/fuzz/holes/). agora #224 (a
`% Drop` destructor reading a view whose source ended first) is closed
in 0.83.0: scope-end drops run newest first, and such a drop is a use of
what the view points into ([`MEMORY.md` §2.14](MEMORY.md)). One
of them is closed at run time rather than at compile time: a handle
whose copies are one state (a `PNCounter`, a `TcpConn`, a `Cell`)
crossing to another thread while a copy of it stays behind panics at the
crossing (`thread_spawn`, `spawn`, `chan_send`, a `Locked`), naming the
handle ([`MEMORY.md` §6.5](MEMORY.md));
the ownership rules of the single-threaded language (`A2.memory_safe`,
`A2.no_leak_end`, phases A1–A2) are mechanically proven sound in Lean 4
([`formal/`](../formal/)).

The fixed grammar quirks (binary `&` / `|` arity, ternary cascading, `^`
vs `^^`) are documented in the [Grammar](#grammar) section below; the
closure-capture and `: ~` closure-borrow-escape rules live in
[`docs/MEMORY.md`](MEMORY.md). All of these are compiler-diagnosed —
"the error message is the API".

## Type system

| Limitation | Workaround |
|---|---|
| Single-letter type keywords (`i u f b s v`) cannot be used as variable names with type inference | Use an explicit type annotation: `: i n expr` |

## Traits

| Limitation | Workaround |
|---|---|
| Bare-name method calls are **statically** dispatched — resolved to `method__<mangled-first-arg-type>` at monomorphisation, with no per-call vtable. Dynamic dispatch **is** supported but must be opted into via the `%Trait` object type + `( dyn Trait value )` construction: a `%dyn.<Trait> = { i8*, i8* }` box-plus-vtable fat pointer (spec §4.9). A trait must be **object-safe** to be used as `%Trait` (see `compiler/tests/should_fail_dyn_not_object_safe.nu`) | Keep the concrete type at the call site for static hot paths; for a heterogeneous collection, box values as `%Trait` with `( dyn Trait v )`, or use an enum of the variants and match |
| Associated types have **no projection**: an associated type cannot be named as `A::Elem` at a generic call site — it is usable only inside the declaring trait's own method bodies/signatures | Make the element an explicit type parameter of the function (`[A E]`) when a caller needs to name it |
| An associated-type binding (`type Elem Concrete`) must be a **single simple type name** (IDENT / type keyword); compound types (`* T`, `Vec T`, `?T`) are not accepted — the same restriction trait-default substitution carries | Bind to a named struct/alias type that wraps the compound type |
| Two type aliases that share an LLVM lowering (`i`/`i64`, `u`/`u8`, `f`/`f64`) cannot both implement the same trait method — they collide on one dispatch key and are reported as a duplicate impl | Pick one spelling per impl; the alias is the same runtime type |

## Concurrency / thread safety

Safe code is held to the ownership rules, data races included
([`MEMORY.md` §6.2](MEMORY.md)). What is trusted rather than checked —
marker assertions — is listed in
[`MEMORY.md` §3, §6.4, and §6.5](MEMORY.md); read those before relying on a
thread-safety expectation the rules do not state.

| Limitation | Workaround |
|---|---|
| `Send` / `Sync` are **derived from a type's structure, not proved**. The compiler knows four built-in cases — `Rc` (non-atomic refcount), `Cell` (raw unsynchronised byte buffer), a library handle (Sync only where asserted) and a trait object (Send only when its trait declares `: Send`) — and propagates them through struct fields, enum payloads, generic arguments, aggregates and closure captures. It knows nothing about an FFI handle: no C pointer is a leaf, however it is spelled — `*u` (as the sqlite declarations take a `sqlite3*`), `s` (as the `raw` stdio pass-throughs `file_raw` / `file_from_raw` carry a `FILE*`) or an integer — so a struct holding a `sqlite3*` or a `FILE*` derives as Send and crosses without a word. Binding a C library takes `unsafe` functions, and marking its handle types is part of what their author vouches for | Mark the type: `% NotSend Db { }` (or `% NotSync`) from `stdlib/core/marker.nu`. It propagates exactly like a built-in leaf — a struct holding it, a `( Vec Db )`, a closure capturing one are all rejected at the boundary. `stdlib/ext/sqlite` marks its own `Database` and `Statement` this way, so that one is handled; every other binding that wraps a C handle still has to say so itself |
| The derivation is also **conservative in the other direction**: a type that is thread-safe by construction but structurally suspect is rejected — one that holds a `Cell` but synchronises access to it itself | Assert it: `unsafe % Send T { }` / `unsafe % Sync T { }` (outside the standard library the `unsafe` prefix is required, [spec §3.3d](spec.md)). An explicit marker stops the walk at that type — nothing inside is examined, because you have taken responsibility for it. This is NURL's spelling of Rust's `unsafe impl`, and a negative marker outranks a positive one on the same type |
| `Send` answers "may this value **move** to another thread", never "is this program race-free". `( Vec i )` and `s` are Send **and** Sync — correctly, because sharing one read-only is ordinary code — so two threads *mutating* one is not caught by this check | It is caught by the move rule: a thread closure moves its captures, so only share handles (`Channel`, `Mutex`, `Arc`, `Locked`, `RwLocked`, `Atomic`, `PFile`) are used on both sides ([`MEMORY.md` §6.5](MEMORY.md)); a mutation through a shared `Arc` is the next row |
| Changing the **contents** of an `Arc` is rejected in safe code — on every thread, the one that made it included, and whatever lock is held. `Arc` makes the refcount atomic, not the payload: every clone reads it without a lock, and `arc_get` over a `Vec`/`String` hands back a handle aliasing the one buffer. A call that hands an `arc_get` result (or a field of one) to anything that changes it — a container mutator, a `String`'s or a map's, a helper, at any depth — is a compile error, and `arc_set` is for `unsafe` code only | Build the value first and `arc_new` it whole; put state threads share and change in a `Locked [T]` (`stdlib/std/thread.nu`: `locked_with` / `locked_set` hold its own lock, so the lock that guards the data is the one its type names), in an `RwLocked [T]` when many threads read it at once (`stdlib/std/rwlock.nu`: a read guard lends a frozen view), or in an `Atomic` for a single word; keep state one thread changes in an `Rc`; or give each thread its own copy and merge after `thread_join` |
| `thread_spawn` / `spawn` take a `( @ v )` closure; the worker runs on its own copy of the captured environment (a closure written in the call is handed over instead of copied), dropped when the body returns ([`docs/MEMORY.md` §7.5](MEMORY.md)). Send covers what the copy *reaches*. The closure moves its owned captures and takes its own share of a `Channel` / `Mutex` / `Arc` / `Locked` (`docs/MEMORY.md` §6.2); a `: ~` by-reference capture may not reach it (§2.3), and a raw `*T` exists only in `unsafe` code | Move shared state to a heap-backed, thread-safe handle before spawning: a `Locked` or a `Channel` for state that changes, an `Arc` for a value nobody changes |
| Module globals in safe code: a mutable scalar global (an integer, bool, float or `s`) is read and written atomically, but a mutable global of a struct or an option is reachable only from `unsafe` code (no atomic covers it), a mutable `s` global holds literals only (safe code may not hand it a string to own: the next assignment would free it under a reader on another thread), and a global set at start holds only a type that synchronises itself — a `Locked`, `Arc`, `Channel`, `Mutex`, `Cond` or `Semaphore`, never a bare `( Vec T )` (h263, h272, h273) | Keep state that changes at run time in a `( Locked T )` global set at start (`: ( Locked T ) g ( make )`, docs/MEMORY.md Module globals); a value nobody changes in an `Arc` |

## Functions and calls

| Limitation | Workaround |
|---|---|
| Calls require explicit parens — `( f a b )` is the only call form; a bare identifier is always a name lookup, never a call | Wrap every callsite: `( puts s )` |
| Struct parameters are passed by **value** by default (C/Go/Zig semantics) — `= . p field val` inside the callee writes a local copy; the caller's struct is unchanged | Mark the parameter `inout` (`@ bump inout Counter c → v`) — an exclusive mutable borrow, the callee mutates the caller's binding in place (see [`docs/MEMORY.md`](MEMORY.md)). Or return the modified struct (`= c ( inc_returning c )`); or use a `*T` parameter inside an `unsafe` function; or wrap state in a single-handle struct (`{ ( Vec i ) slots }`) |
| A closure hands its result to its caller as the caller's own, so it cannot hand back a value it does not own that cannot be copied (a `% Drop` value with no clone — its parameter, its capture, a field of either, what a lending call lent), nor a view (a Slice, a struct of views) of what it captured; a raw string it lent comes back a copy (docs/MEMORY.md, h219/h220) | Hand back a value the body makes, or take what the view points into as an argument — a view of an argument is followed at the call. A plain function may lend its parameter or a field of one |
| A function cannot hand back a field that cannot be copied out of a struct it drops, a module global or a capture (h221) | Keep the value in a binding of its own and hand that back, or hand back the whole struct |
| A closure that moves out a capture it cannot copy (a `% Drop` value with no clone) runs at most once — one that may leave its frame and is run again after the move, or after a copy of it (a thread's) took the value, stops with a panic (h222, h236, h239, h244) | Pass the value as an argument, or move it in a closure that is run once |
| A closure that may leave its frame (handed back, to a thread, a fiber or a callee, or bound to a name used other than as a callee) takes a capture it cannot copy from the frame when it is made, even one it only reads: the frame cannot use the value after that (h240–h243) | Make the closure after the frame's last use of the value, or call the closure only by name so it stays in the frame |
| A function cannot hand back a view of a `sink` parameter it drops (h225) | Take the parameter by lend (no `sink`), or hand back the value itself |
| A value that cannot be copied which a call only lends (`vec_at` of a `( Vec Res )`) cannot be stored, pushed or handed to a `sink`; nor can such a field be moved out of a struct that still drops it (h229, h230) | Take it out of its owner first (`vec_pop`, `vec_remove`, replacing the field), or lend it |
| A value that cannot be copied which a call lends out of one of the function's own locals (`^ ( getr h )` with `h` local, or a binding of it — `: D d \ ( getr h )`) cannot be handed back, assigned to an `inout` parameter, stored, pushed or put in a literal: the local releases it on the way out (agora #187, #196, #200; h918–h925) | Take it out of its owner (`vec_remove`, `vec_pop`, a function that hands it over) and hand that back, or hand back the owner itself |
| A generic that copies its `T` (`box_clone`, anything built on `mem_dup`) cannot be instantiated with a value that cannot be copied; the error points at the copy inside the generic, not at the call (h235) | Move the value instead, or give the type a clone |
| A match arm cannot hand an enum's payload that cannot be copied to a `sink` or an owner: the enum keeps it (h231) | Match on the enum to read the payload; to take it out, give the enum a variant constructor that hands it back from a function that takes the enum as `sink` |
| A match cannot hand a payload it only borrows that cannot be copied — of an option a struct field keeps — to the binding it initialises (h227) | Read the payload in the arm, or take the option out of the struct first |
| A closure whose body changes a capture (grows, clears or replaces it) cannot be handed to a call, or called, beside another argument that reaches that capture — the binding, a borrow or view of it, or another closure that captured it — and cannot itself hold a view of that capture (h274–h280) | Hand the callee what it needs as a parameter instead of capturing it, as `ws_serve_messages_deflate_with_context` gives its handler the deflate context ([`MEMORY.md` §2.11](MEMORY.md)) |
| A closure captures by pointer into its caller's frame a `: ~` binding it assigns or hands to an `inout` parameter, and a `: ~` multi-field struct (a callback counts into its caller's binding; `recover \ → v { = out ( f ) }` hands a result out); such a closure cannot leave the frame — returned, stored in a container, or handed to a thread, a fiber (`spawn*`) or `signal_install` ([`docs/MEMORY.md` §2.3](MEMORY.md)). Every other capture is copied when the closure is made | Keep state a closure that outlives its frame changes in a heap-backed handle: an `Atomic`, a `Locked`, an `Rc` |
| A parameter may not be named `r` followed only by digits (`r0`, `r12`, …) — a by-value parameter keeps its source name as its LLVM SSA register, and nurlc's temporaries are `%r0`, `%r1`, … in the same namespace | Rename it (`r0` → `r_0`, or something that says what it holds). Locals are unaffected — the code generator names those |
| A `sink` parameter owns and drops what it is given — a `String`, `Vec`, owning struct, handle enum, library handle, `Drop` value or a raw `s` (docs/MEMORY.md §1, §7.6). An **owned slice**, or a struct whose literal gave it one, is still **rejected at the call site**: its auto-drop obligation is not transferred | Pass an owned slice as an ordinary parameter and let the caller's scope drop it, or use a `Vec` |

## Ownership

| Limitation | Workaround |
|---|---|
| Freeing a field of a match payload (`?? o { T t → ( string_free . t name ) }`) hands the rest of the payload to the arm: it is dropped at the arm's end, and `o` must not be read after that match | Take the payload whole (`: Tagged x t`), or free the field after the last use of `o` |
| Storing a *borrowed* `String` / `Vec` into an owner (a struct literal, a field of a value, an element via `vec_push`) stores a **copy**; mutations through the new owner are not seen through the old binding | Store the owned value (move it in), or keep the shared buffer behind a pointer-reached struct, whose fields are stored as is |
| An element borrowed out of a temporary container (`( vec_get [T] ( mk ) 0 )`) is copied before the temporary is dropped; when `T` cannot be copied (a `% Drop` struct with no clone) that is an error, since nothing would own the temporary | Bind the container to a name first (`: ( Vec T ) v ( mk )`): it lives to the end of its scope, and the element borrows from it |

## Imports

| Limitation | Workaround |
|---|---|
| `import_decl` is a static inline-include (like `#include`) — the imported file is compiled into the same LLVM module | Avoid importing files that define `main`; avoid circular imports |
| Import alias (`` $ `path` alias ``) rewrites top-level `@`-functions, struct/enum types, enum variants, and global `:` constants to `alias__name`. FFI decls (`& "lib" @ name`) and trait/impl methods are intentionally NOT renamed — FFI symbols resolve at the linker by literal C-ABI name, and trait methods are mangled by the impl-target type | Use `pub` to scope FFI declarations to the importing file if collision is a risk |
| `pub` visibility covers `@`-functions, struct/enum types, enum variants (inheriting their enum's flag), and global `:` constants. Files with no `pub` decl stay in legacy mode (everything public, backwards-compat). FFI and trait/impl decls accept `pub` forward-compat but do not enforce | Mark each cross-file API entry with `pub`; the diagnostic `private X 'Y' is not visible across files` points at the leaked-private use site |
| `$`-import dedup keys on the `realpath(3)`-canonical file, so the same file reached through different symlink chains compiles exactly once; only when `realpath` itself fails (exotic filesystems) does dedup fall back to the normalised path string | None needed in practice; prefer the project-root-relative form (`stdlib/foo.nu`) for readability |

## Grammar

| Limitation | Workaround |
|---|---|
| Import is inline-include only: no namespaces. Alias rewriting covers `@`-functions, struct/enum types, enum variants, and global `:` constants; FFI decls and trait/impl methods are deliberately not renamed | Stick to a single canonical import path per file; prefix FFI names manually when collisions matter |
| **Every operator has fixed arity** (prefix notation has no closing token — a **locked 1.0 design decision**, see [`docs/spec.md` §6](spec.md); not a deferred gap). `&` / `\|` / `^^` / `+` / `-` / `*` / `/` / `==` / `!=` / `<` / `>` / `<=` / `>=` / `<<` / `>>` are all **binary** (`OP A B`); `?` ternary is `? cond then else`; `^` / `!` / `~` are unary. A missing or extra operand silently consumes the next token, so the diagnostic can land on the following line (when the swallowed line uses the binding being initialised, nurlc names the cause instead: "the initialiser of 'b' is one operand short and swallowed the statement on line N") | Count operands left-to-right when "unexpected token" fires on a line that looks fine. For n-ary `&`/`\|` chains write `& A & B C` or `& & & A B C D` (n−1 operators for n atoms), or factor a predicate helper (`is_alpha`-style); the compiler rejects the common `? & A B C D { … } { … }` shape as a hard error by default (`nurlc --no-strict-arity` demotes it to a warning; this repo additionally runs `tools/check_strict_arity.sh` over its whole tree in CI) |
| **`^` is the `return` keyword, not XOR** — but `^^` (two adjacent carets) **is** the native XOR operator. `^ a b` parses as `return (a b …)` | Use `^^` for XOR. The lexer pairs `^^` only when the carets are adjacent, so a stray space (`^ ^`) still means two returns |
| **Nesting depth is limited** (Agora #207). nurlc stops with a diagnostic past 1000 levels of expressions, blocks and types inside one another, instead of running out of stack. A nested `?` statement with its block counts as about three levels, a call or an operator as one or two. The playground fixes the limit at 200 | Split deep code into functions or bind intermediate values. Generated code that needs more passes `--max-nesting=N` or sets `NURL_MAX_NESTING=N` (0 turns the limit off); nesting much deeper than the default can also need a larger stack (`ulimit -s`) |
